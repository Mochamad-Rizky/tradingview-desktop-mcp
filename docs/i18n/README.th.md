เซิร์ฟเวอร์ [MCP](https://modelcontextprotocol.io) ที่ช่วยให้ผู้ช่วย AI อ่านและควบคุมแอป TradingView
Desktop บนเครื่องของคุณเองได้ เซิร์ฟเวอร์จะควบคุมแอปที่คุณล็อกอินอยู่แล้วผ่าน Chrome DevTools Protocol
โดยใช้พอร์ตดีบักที่แอปเปิดไว้เมื่อเริ่มทำงานด้วย `--remote-debugging-port` เซิร์ฟเวอร์ทำงานอัตโนมัติกับแอป
บนเครื่องเท่านั้น: ไม่ล็อกอินแทนคุณ ไม่หลบเลี่ยงขีดจำกัดของแผนสมาชิก และไม่เรียกเซิร์ฟเวอร์ของ
TradingView

> **สถานะ: ก่อนเวอร์ชัน 1.0** ชื่อเครื่องมือและตัวเลือกอาจเปลี่ยนแปลงก่อนถึง 1.0 ติดตั้งแพ็กเกจจาก npm
> ตามขั้นตอนด้านล่าง หรือรันเซิร์ฟเวอร์[จากซอร์สโค้ด](#quick-start-from-source) ได้ทดสอบบน macOS แล้ว
> ส่วน Windows และ Linux รองรับเท่าที่ทำได้

เซิร์ฟเวอร์มีเครื่องมือของแอป (เปิดแอป ตรวจสุขภาพ ค้นหาแอป สถานะอินเทอร์เฟซ ขีดจำกัดของแผน
เชื่อมต่อใหม่) เครื่องมือกราฟ (สถานะ สัญลักษณ์ ไทม์เฟรม ประเภทกราฟ ช่วงที่มองเห็น การเลื่อน)
เครื่องมือข้อมูลตลาด (แท่งราคา ราคาล่าสุด ข้อมูลและการค้นหาสัญลักษณ์) เครื่องมืออินดิเคเตอร์ (แสดงรายการ
ค้นหา เพิ่ม ลบ อินพุต การแสดงผล ค่า) เครื่องมือ Pine Script (เอดิเตอร์และสคริปต์ที่บันทึกไว้ คอมไพล์
สมาร์ตคอมไพล์ที่แก้ไขตามกฎ การวิเคราะห์แบบออฟไลน์ คอนโซล และเส้น ป้ายกำกับ กล่อง และตารางที่สคริปต์วาด)
เครื่องมือ Strategy Tester (ผลลัพธ์ รายการเทรด เส้นทุน) เครื่องมือวาด การแจ้งเตือน และรายการเฝ้าดู
เครื่องมือเลย์เอาต์ หลายกราฟ และแท็บ บาร์รีเพลย์ ภาพหน้าจอ เครื่องมืออินเทอร์เฟซระดับล่าง (คลิก โฮเวอร์
พิมพ์ ปุ่มคีย์บอร์ด เลื่อน ค้นหา แผง เต็มหน้าจอ และ JavaScript ในหน้ากราฟเมื่อคุณอนุญาต) และ
`batch_run` ซึ่งรันหลายเครื่องมือในการเรียกครั้งเดียว นอกจากนี้ยังมีรีซอร์ส (สุขภาพของแอป สถานะกราฟและ
แท่งราคา ซอร์ส Pine และผลคอมไพล์ล่าสุด รายงานกลยุทธ์ รายการเฝ้าดูที่ใช้งานอยู่) ซึ่งแต่ละรายการมาพร้อมกับ
เครื่องมือที่ใช้ข้อมูลร่วมกัน และพรอมต์ห้ารายการสำหรับงานที่ทำบ่อย เว็บแดชบอร์ดแสดงการเรียกแบบเรียลไทม์
และให้คุณรันเครื่องมือด้วยตนเองได้ (ดู[แดชบอร์ด](#dashboard))

## <a id="install-by-asking-your-ai-app"></a>ติดตั้งโดยสั่งแอป AI ของคุณ

คุณไม่จำเป็นต้องพิมพ์คำสั่งใด ๆ เอง หากแอป AI ของคุณรันคำสั่งบนคอมพิวเตอร์ได้ อย่างที่ Claude Code,
Cursor, VS Code, Windsurf, Gemini CLI และ Codex CLI ทำได้ แอปก็จะตั้งค่าให้คุณได้ ก่อนอื่น:

1. ติดตั้ง [TradingView Desktop](https://www.tradingview.com/desktop/) แล้วล็อกอิน
2. ติดตั้ง [Node.js](https://nodejs.org) (เวอร์ชัน LTS) หากยังไม่มี

จากนั้นคัดลอกพรอมต์นี้ วางลงในแอป AI ของคุณ แล้วส่ง:

```text
ช่วยติดตั้งเซิร์ฟเวอร์ TradingView MCP ให้หน่อย เป็นแพ็กเกจ npm ชื่อ tradingview-desktop-mcp
(https://github.com/Mochamad-Rizky/tradingview-desktop-mcp) ทำตามขั้นตอนเหล่านี้ และอธิบายแต่ละขั้นตอน
ให้ฉันฟังด้วยภาษาง่าย ๆ:

1. ตรวจสอบว่าติดตั้ง Node.js 20.19 ขึ้นไปแล้ว ถ้ายังไม่ได้ติดตั้ง ให้หยุดและบอกวิธีติดตั้งให้ฉัน
2. รัน "npx -y tradingview-desktop-mcp config <client>" โดยให้ <client> เป็นแอปที่คุณกำลังทำงานอยู่
   (claude-code, cursor, vscode, windsurf, gemini-cli หรือ codex-cli) ทำตามสิ่งที่คำสั่งแสดงออกมา
   เพื่อเพิ่มเซิร์ฟเวอร์ลงในการตั้งค่าของฉัน และเก็บเซิร์ฟเวอร์อื่นที่มีอยู่แล้วไว้ตามเดิม
3. เปิด TradingView ด้วย "npx -y tradingview-desktop-mcp launch" ถ้าแจ้งว่า TradingView กำลังทำงาน
   อยู่แล้วโดยไม่มีพอร์ตดีบัก ให้ถามฉันก่อน และรันอีกครั้งพร้อม --restart เฉพาะเมื่อฉันตกลงเท่านั้น
   เพราะคำสั่งนั้นจะปิด TradingView และฉันอาจสูญเสียการเปลี่ยนแปลงที่ยังไม่ได้บันทึก
4. รัน "npx -y tradingview-desktop-mcp doctor" แล้วบอกฉันว่าผ่านการตรวจสอบทั้งหมดหรือไม่ ถ้าการ
   ตรวจสอบกราฟไม่ผ่าน ให้บอกฉันให้นำแท็บกราฟใน TradingView ขึ้นมาไว้ด้านหน้า
5. บอกฉันว่าต้องรีสตาร์ตคุณ หรือเปิดแชตใหม่ ก่อนที่เครื่องมือของ TradingView จะปรากฏหรือไม่
```

เมื่อเสร็จแล้ว ให้รีสตาร์ตแอปหรือเปิดแชตใหม่หากผู้ช่วยบอกให้ทำ แล้วถามว่า "ตรวจสอบว่า TradingView
เชื่อมต่ออยู่หรือไม่" จากนั้นลองใช้[พรอมต์ด้านล่าง](#try-these-prompts)

ใช้ Claude Desktop อยู่ใช่ไหม? Claude Desktop รันคำสั่งไม่ได้ แต่ Claude Code, Cursor และแอปอื่น ๆ
ข้างต้นตั้งค่าให้ได้: เพิ่มข้อความ "ตั้งค่าสำหรับ Claude Desktop (config claude-desktop) ไม่ใช่สำหรับแอปนี้"
ไว้ท้ายพรอมต์ ChatGPT และ OpenAI API ต้องใช้ทันเนล ซึ่งคุณต้องตั้งค่าเอง (ดู
[ไคลเอนต์ระยะไกลและทันเนล](#remote-clients-and-tunnels)) หากผู้ช่วยติดขัด ให้ทำตามขั้นตอนด้านล่าง
ด้วยตนเอง

## <a id="install"></a>การติดตั้ง

สิ่งที่ต้องมี:

- TradingView Desktop ที่ติดตั้งและล็อกอินแล้ว
- Node.js 20.19 ขึ้นไป ซึ่งมาพร้อม `npx`

ไม่ต้องติดตั้งอะไรเพิ่ม: ไคลเอนต์ด้านล่างจะเริ่มเซิร์ฟเวอร์ด้วย `npx -y tradingview-desktop-mcp`
ซึ่งจะดาวน์โหลดแพ็กเกจเมื่อใช้งานครั้งแรก ให้เปิด TradingView พร้อมพอร์ตดีบัก คำสั่ง `launch`
จะค้นหาแอปและเปิดแอปด้วยวิธีนั้น:

```sh
npx -y tradingview-desktop-mcp launch
```

TradingView อนุญาตให้เปิดได้เพียงอินสแตนซ์เดียว หากแอปทำงานอยู่แล้วโดยไม่มีพอร์ตดีบัก `launch`
จะหยุดและแจ้งให้ทราบ ส่วน `launch --restart` จะปิดแอปอย่างนุ่มนวลแล้วเปิดใหม่พร้อมพอร์ต และ
TradingView อาจขอให้คุณบันทึกการเปลี่ยนแปลงก่อน ตรวจสอบว่าเซิร์ฟเวอร์เข้าถึงแอปได้:

```sh
npx -y tradingview-desktop-mcp doctor
```

`doctor` จะไม่ผ่านการตรวจสอบกราฟขณะที่แท็บกราฟอยู่เบื้องหลัง ถูกบังด้วยหน้า New tab หรือแท็บอื่น
ที่ไม่มีกราฟ ดังนั้นให้นำแท็บกราฟขึ้นมาไว้ด้านหน้า
`npx -y tradingview-desktop-mcp --help` จะแสดงรายการตัวเลือก และ [.env.example](../../.env.example)
จะแสดงตัวแปรสภาพแวดล้อม

## <a id="connect-your-ai-app"></a>เชื่อมต่อแอป AI ของคุณ

`config <client>` จะแสดงโค้ดตั้งค่า (snippet) ของไคลเอนต์และบอกว่าต้องวางไว้ที่ใด บทแนะนำแต่ละรายการ
ด้านล่างมีโค้ดเดียวกันนี้ ขั้นตอนสำหรับแอปนั้น และสิ่งที่ต้องทำเมื่อใช้งานไม่ได้

| ไคลเอนต์                                       | แสดงโค้ดตั้งค่า                                        |
| ---------------------------------------------- | ------------------------------------------------------ |
| [Claude Desktop](../clients/claude-desktop.md) | `npx -y tradingview-desktop-mcp config claude-desktop` |
| [Claude Code](../clients/claude-code.md)       | `npx -y tradingview-desktop-mcp config claude-code`    |
| [Cursor](../clients/cursor.md)                 | `npx -y tradingview-desktop-mcp config cursor`         |
| [VS Code](../clients/vscode.md)                | `npx -y tradingview-desktop-mcp config vscode`         |
| [Windsurf](../clients/windsurf.md)             | `npx -y tradingview-desktop-mcp config windsurf`       |
| [Gemini CLI](../clients/gemini-cli.md)         | `npx -y tradingview-desktop-mcp config gemini-cli`     |
| [Codex CLI](../clients/codex-cli.md)           | `npx -y tradingview-desktop-mcp config codex-cli`      |
| [ChatGPT](../clients/chatgpt.md)               | `npx -y tradingview-desktop-mcp config chatgpt`        |
| [OpenAI API](../clients/openai-api.md)         | `npx -y tradingview-desktop-mcp config openai-api`     |

ทรานสปอร์ตเริ่มต้นคือ stdio ซึ่ง stdout ใช้ส่งเฉพาะข้อความ MCP และล็อกจะออกทาง stderr ไคลเอนต์เจ็ด
รายการแรกจะเริ่มเซิร์ฟเวอร์เอง บน Windows ไคลเอนต์ที่เริ่ม `npx` โดยตรงไม่ได้จะต้องใช้รูปแบบ
`cmd /c npx` ซึ่ง `config` จะแสดงให้เมื่อรันบน Windows (หรือเมื่อใช้ `--platform win32`) ส่วน
`--profile` จะส่ง[โปรไฟล์เครื่องมือ](#tool-profiles)ต่อไปยังเซิร์ฟเวอร์

### <a id="remote-clients-and-tunnels"></a>ไคลเอนต์ระยะไกลและทันเนล

ChatGPT และ OpenAI API ไม่สามารถเริ่มโปรแกรมบนคอมพิวเตอร์ของคุณได้ ทั้งสองเข้าถึงเซิร์ฟเวอร์ผ่านที่อยู่
HTTPS สาธารณะ คุณจึงต้องรันเซิร์ฟเวอร์ผ่าน HTTP และวางทันเนลไว้ด้านหน้า การทำเช่นนี้เท่ากับนำเซิร์ฟเวอร์
ที่ควบคุม TradingView ที่คุณล็อกอินอยู่ได้ขึ้นไปไว้บนอินเทอร์เน็ต: ให้ใช้ `--profile readonly` โทเค็นที่
คาดเดายาก (`TV_MCP_AUTH_TOKEN`) ระบุโฮสต์สาธารณะของทันเนลใน `--allowed-hosts`
(`TV_MCP_ALLOWED_HOSTS`) และใช้ `--no-dashboard` เพื่อไม่ให้ไฟล์ของแดชบอร์ดถูกเผยแพร่ผ่านทันเนล
บทแนะนำสำหรับ [ChatGPT](../clients/chatgpt.md) และ [OpenAI API](../clients/openai-api.md)
จะพาทำทีละขั้นตอน และ [SECURITY.md](../../SECURITY.md#tunnels-and-remote-clients) ระบุสิ่งที่โทเค็นแบบ
อ่านอย่างเดียวยังเข้าถึงได้

## <a id="quick-start-from-source"></a>เริ่มต้นอย่างรวดเร็วจากซอร์สโค้ด

หากต้องการรันโค้ดที่เช็กเอาต์มาแทนแพ็กเกจที่เผยแพร่แล้ว คุณต้องใช้ Node.js 24 ในการบิลด์เซิร์ฟเวอร์
(`nvm use` จะอ่าน `.nvmrc`) และ [pnpm](https://pnpm.io) ซึ่งเวอร์ชันถูกกำหนดไว้ใน `package.json`
เซิร์ฟเวอร์ที่บิลด์แล้วทำงานบน Node.js 20.19 ขึ้นไป

```sh
git clone https://github.com/Mochamad-Rizky/tradingview-desktop-mcp.git
cd tradingview-desktop-mcp
pnpm install && pnpm build
node packages/server/dist/cli.js launch
node packages/server/dist/cli.js doctor
```

`node packages/server/dist/cli.js config <client> --local` จะแสดงโค้ดตั้งค่าของไคลเอนต์สำหรับโค้ด
ที่เช็กเอาต์นี้ โดยใช้ `node` และพาธแบบสัมบูรณ์ของ `cli.js` แทน `npx` สำหรับไคลเอนต์ที่ตั้งค่าด้วย
JSON รายการจะมีลักษณะดังนี้:

```json
{
  "mcpServers": {
    "tradingview": {
      "command": "node",
      "args": ["/absolute/path/to/tradingview-desktop-mcp/packages/server/dist/cli.js"]
    }
  }
}
```

นอกจากนี้ยังมีทรานสปอร์ต HTTP (`--transport http`) โปรดอ่าน [SECURITY.md](../../SECURITY.md) ก่อน
ใช้งาน

## <a id="use-it"></a>การใช้งาน

เชื่อมต่อไคลเอนต์ MCP ตามที่อธิบายไว้ข้างต้น โดยให้ TradingView ทำงานพร้อมพอร์ตดีบัก แล้วบอกสิ่งที่
ต้องการด้วยภาษาธรรมดา ผู้ช่วยจะเลือกเครื่องมือและเรียกใช้เอง คุณจึงไม่จำเป็นต้องรู้ชื่อเครื่องมือ
[เอกสารอ้างอิงเครื่องมือ](../tools.md) แสดงเครื่องมือทุกตัวพร้อมอินพุตและโปรไฟล์ที่เครื่องมือนั้น
สังกัดอยู่

### <a id="try-these-prompts"></a>ลองใช้พรอมต์เหล่านี้

พรอมต์แต่ละรายการด้านล่างเป็นหนึ่งในตัวอย่างใน [docs/examples.md](../examples.md) ซึ่งแสดงการเรียก
เครื่องมือที่ผู้ช่วยทำและผลลัพธ์ โดยตัดรายการที่ยาวเกินสามรายการ ละเว้นระยะเวลาของการเรียกแต่ละครั้ง
(`durationMs`) และระบุชื่อภาพหน้าจอไว้ในหมายเหตุแทนการแสดงภาพ ส่วนที่ยกมาคือบรรทัดจากผลลัพธ์
เหล่านั้น และ `…` ระบุตำแหน่งที่ละบรรทัดของส่วนอื่นในผลลัพธ์ไว้ ค่าทั้งหมดเป็นข้อมูลสังเคราะห์:
มาจากแอป TradingView จำลองที่มีกราฟ NASDAQ:AAPL สมมติ จึงไม่มีข้อมูลใดเป็นข้อมูลตลาดและไม่มีข้อมูลใด
มาจากบัญชีจริง ผลลัพธ์มีรูปแบบเดียวกับที่เซิร์ฟเวอร์ส่งกลับมา แม้ว่ารายงาน Strategy Tester ที่อยู่เบื้องหลัง
ตัวอย่างการทดสอบย้อนหลังจะยังไม่เคยอ่านจากแอปจริงก็ตาม

**"บนกราฟของฉันตอนนี้แสดงอะไรอยู่? บอกสัญลักษณ์ ไทม์เฟรม และอินดิเคเตอร์ที่อยู่บนกราฟ"** ผู้ช่วยจะ
อ่านกราฟด้วย `chart_get_state`
([รายละเอียด](../examples.md#1-read-the-chart)):

```json
"symbol": "NASDAQ:AAPL",
"resolution": "1D",
"chartTypeName": "candles",
```

**"แสดงแท่งเทียนรายวัน 3 แท่งล่าสุดให้ดูหน่อย"** ผู้ช่วยจะอ่านแท่งราคาด้วย `data_get_ohlcv`
([รายละเอียด](../examples.md#3-read-the-last-candles)):

```json
"timeIso": "2024-10-27T00:00:00Z",
"open": 103.58,
"close": 103.42,
```

**"เพิ่ม MACD ลงในกราฟของฉัน"** บนกราฟที่มีอินดิเคเตอร์ครบตามจำนวนที่แผนอนุญาตแล้ว `indicator_add`
จะไม่เพิ่มอะไรและรายงานขีดจำกัด และการลบอินดิเคเตอร์ตัวใดตัวหนึ่งของคุณออกเพื่อให้มีที่ว่างต้องได้รับ
การยืนยันจากคุณ ([รายละเอียด](../examples.md#5-add-an-indicator-to-a-full-chart)):

```json
"code": "PLAN_LIMIT",
"message": "The chart holds as many indicators as the plan allows (2)",
```

**"เขียนอินดิเคเตอร์ Pine Script ที่พล็อตเส้นค่าเฉลี่ยเคลื่อนที่ 9 แท่งและ 21 แท่งของราคาปิด แล้วตรวจสอบ
ว่าคอมไพล์ผ่าน"** ผู้ช่วยจะใส่สคริปต์ลงใน Pine Editor ด้วย `pine_new` และคอมไพล์ด้วย `pine_compile`
([รายละเอียด](../examples.md#6-write-and-compile-a-pine-script)):

```json
"success": true,
"errors": [],
"warnings": [],
```

**"สคริปต์ใน Pine Editor ของฉันคอมไพล์ไม่ผ่าน ช่วยแก้ให้หน่อยได้ไหม?"** `pine_smart_compile` จะคอมไพล์
สคริปต์ ใช้การแก้ไขตามกฎกับข้อผิดพลาดที่รู้จัก เช่น ชื่อแบบ Pine v4 ในสคริปต์ v6 แล้วคอมไพล์อีกครั้ง
โดยไม่เปลี่ยนแปลงเนื้อหาในเอดิเตอร์
([รายละเอียด](../examples.md#7-fix-a-pine-script-with-smart-compile)):

```json
"message": "Could not find function or function reference 'study'",
…
"applied": ["Replace study( with indicator(", "Replace rsi( with ta.rsi("]
…
"writtenBack": false
```

**"กลยุทธ์บนกราฟของฉันทำผลงานในการทดสอบย้อนหลังได้อย่างไร?"** ผู้ช่วยจะอ่าน Strategy Tester ด้วย
`strategy_get_results` และ `strategy_get_trades`
([รายละเอียด](../examples.md#8-read-backtest-results)):

```json
"netProfit": 155,
"totalTrades": 3,
"percentProfitable": 66.67,
"profitFactor": 4.1,
```

**"วาดเส้นแนวรับที่ 102.80 บนกราฟของฉัน"** ผู้ช่วยจะวาดเส้นแนวนอนด้วย `drawing_create` และ
`drawing_list` จะแสดงเส้นนี้ข้างภาพวาดของคุณเอง โดยระบุว่าวาดโดยเซสชันนี้
([รายละเอียด](../examples.md#9-draw-a-support-line)):

```json
"id": "DRW001",
"shape": "horizontal_line",
"text": "Support",
"createdByServer": true
```

**"แจ้งเตือนฉันเมื่อ Apple ตัดผ่าน 110"** `alert_create` จะตั้งการแจ้งเตือนราคาในบัญชี TradingView
ของคุณ ([รายละเอียด](../examples.md#10-create-a-price-alert)) เมื่อแผนมีการแจ้งเตือนครบตามจำนวน
ที่อนุญาตแล้ว จะไม่สร้างอะไรและรายงานขีดจำกัด และ `alert_list` จะแสดงการแจ้งเตือนที่ใช้โควตาอยู่
([รายละเอียด](../examples.md#11-create-an-alert-when-the-plan-is-full)):

```json
"symbol": "NASDAQ:AAPL",
"condition": "crossing",
"price": 110,
"expirationIso": "2024-11-26T00:00:00Z"
```

**"เพิ่มสัญลักษณ์เหล่านี้ลงในรายการเฝ้าดูของฉัน: NYSE:IBM, FX:EURUSD, NASDAQ:MSFT และ NASDAQ:MSTF"**
`watchlist_add_bulk` จะตรวจสอบแต่ละสัญลักษณ์ด้วยการค้นหาสัญลักษณ์ของ TradingView เพิ่มสัญลักษณ์ใหม่
และบอกเหตุผลที่ข้ามสัญลักษณ์อื่น ([รายละเอียด](../examples.md#12-add-symbols-to-a-watchlist)):

```json
"added": ["NYSE:IBM", "FX:EURUSD"],
…
{ "symbol": "NASDAQ:MSFT", "reason": "already_listed" },
{ "symbol": "NASDAQ:MSTF", "reason": "unknown" }
```

**"ขอฝึกด้วยบาร์รีเพลย์บนกราฟของฉันตั้งแต่ 2024-06-03: เดินหน้าห้าแท่ง บอกว่าตอนนี้อยู่ที่จุดไหน
แล้วจบรีเพลย์"** ผู้ช่วยจะเริ่มบาร์รีเพลย์ด้วย `replay_start` เดินหน้าด้วย `replay_step` อ่านตำแหน่ง
ปัจจุบันของรีเพลย์ด้วย `replay_status` และออกจากรีเพลย์ด้วย `replay_stop` ไม่มีการซื้อขายใด ๆ
เกิดขึ้น: ไม่มีเครื่องมือใดส่งคำสั่งซื้อขาย ([รายละเอียด](../examples.md#13-practice-with-bar-replay)):

```json
"dateIso": "2024-06-07T00:00:00Z",
"stepped": 5,
…
"position": null,
"realizedPL": null
```

**"ถ่ายภาพหน้าจอกราฟของฉัน"** `screenshot_capture` จะส่งภาพให้ผู้ช่วยในรูปแบบรูปภาพพร้อมขนาด
และไม่เขียนอะไรลงดิสก์
([รายละเอียด](../examples.md#14-take-a-screenshot)):

```json
"data": { "target": "chart", "format": "jpeg", "width": 1180, "height": 640, "bytes": 3100 },
"meta": { "via": "cdp", "warnings": [] }
```

เซิร์ฟเวอร์ยังมีพรอมต์ของตัวเองห้ารายการ ซึ่งไคลเอนต์ที่รองรับพรอมต์ของ MCP จะแสดงให้คุณเลือก:
`analyze_current_chart`, `multi_timeframe_review`, `write_and_backtest_strategy`,
`debug_pine_script` และ `replay_practice_session` แต่ละรายการจะบอกผู้ช่วยว่าต้องเรียกเครื่องมือใด
ในลำดับใด และต้องรายงานอะไรกลับมา `replay_practice_session` จะจัดเซสชันฝึกซ้อมบนบาร์รีเพลย์:
ผู้ช่วยจะเดินผ่านอดีตทีละแท่ง ถามคุณในแต่ละขั้นว่าจะเปิด long เปิด short หรืออยู่นอกตลาด จดบันทึก
การเทรดสมมติเหล่านี้ด้วยราคาที่อ่านจากกราฟ และคำนวณกำไรหรือขาดทุน ผู้ช่วยจะตรวจสอบก่อนว่ามีรีเพลย์
ของคุณกำลังทำงานอยู่หรือไม่ และถามคุณว่าจะทำอย่างไรกับรีเพลย์นั้นก่อนจะเปลี่ยนแปลงสิ่งใด เมื่อจบ
ผู้ช่วยจะหยุดเฉพาะรีเพลย์ที่ตัวเองเริ่มไว้ และจะไม่หยุดรีเพลย์ของคุณเลย

### <a id="safety"></a>ความปลอดภัย

เครื่องมือที่เปลี่ยนแปลงกราฟ สคริปต์ หรือบัญชีของคุณจะระมัดระวังกับสิ่งที่เป็นของคุณอยู่แล้ว การแทนที่
ข้อความที่ยังไม่ได้บันทึกใน Pine Editor (ยกเว้นการแก้ไขที่ยังไม่ได้บันทึกซึ่งเซสชันนี้ของเซิร์ฟเวอร์ทำไว้เอง)
การบันทึกเวอร์ชันใหม่ของสคริปต์ที่เซสชันนี้ไม่ได้สร้าง และการลบอินดิเคเตอร์ที่มีอยู่บนกราฟของคุณอยู่แล้ว
ล้วนต้องใช้ `confirm: true` ซึ่งผู้ช่วยควรส่งก็ต่อเมื่อคุณตกลงแล้วเท่านั้น เช่นเดียวกับการลบภาพวาด
การแจ้งเตือน สัญลักษณ์ในรายการเฝ้าดู หรือแท็บที่เซสชันนี้ไม่ได้สร้าง เพิ่ม หรือเปิด การลบภาพวาดทั้งหมด
ของกราฟ การสลับออกจากเลย์เอาต์ที่มีการเปลี่ยนแปลงที่ยังไม่ได้บันทึก และการเปลี่ยนไปใช้เลย์เอาต์หลายกราฟ
ที่มีจำนวนกราฟน้อยกว่าที่แท็บแสดงอยู่ ซึ่งการบันทึกครั้งถัดไปจะทำให้กราฟที่เหลือหายไป ขีดจำกัดของแผน
เช่น จำนวนอินดิเคเตอร์บนกราฟ จำนวนสคริปต์ที่บันทึกไว้ จำนวนการแจ้งเตือน หรือจำนวนกราฟในเลย์เอาต์
จะถูกตรวจสอบก่อนเพิ่มสิ่งใด และรายงานเป็นข้อผิดพลาด `PLAN_LIMIT` พร้อมค่าขีดจำกัด หากอ่านขีดจำกัด
จาก TradingView บิลด์ของคุณไม่ได้ เครื่องมือจะไม่ทำอะไรและแจ้งให้ทราบ เซิร์ฟเวอร์ไม่หลบเลี่ยงขีดจำกัด
เครื่องมือจะตรวจสอบก่อนว่าอะไรจะทำให้ TradingView เปิดหน้าต่างอัปเกรด หรือหน้าต่างอื่นของตัวเอง
แล้วปฏิเสธแทน แต่ยังมีข้อความแจ้งบางอย่างที่การตรวจสอบเหล่านี้คาดการณ์ไม่ได้: `layout_switch` อาจเจอ
ข้อความชวนอัปเกรดสำหรับเลย์เอาต์หลายกราฟที่บันทึกไว้เมื่ออยู่บนแผนที่รองรับกราฟน้อยกว่า สำหรับเลย์เอาต์
ที่เซิร์ฟเวอร์ของ TradingView ปฏิเสธเพราะเกินขีดจำกัด และสำหรับเลย์เอาต์ที่รายการซึ่ง TradingView
เก็บไว้เองระบุว่าเกินขีดจำกัดแต่ `layout_list` ไม่ได้ระบุ `layout_new` อาจเจอข้อความของ TradingView
เมื่อ TradingView ปฏิเสธเลย์เอาต์ใหม่หลังผ่านการตรวจสอบแล้ว และ `tab_close` อาจเจอหน้าต่าง
"Close tab?" สำหรับหน้าที่ใช้เวลานานกว่าที่ TradingView รอเพื่อบอกว่าเลย์เอาต์มีการเปลี่ยนแปลงที่ยังไม่ได้
บันทึกหรือไม่ หรือหน้าที่รายงานว่ากำลังบันทึกวิดีโออยู่ เครื่องมือ `ui_*` ระดับล่างจะคลิกและพิมพ์ตามที่
คุณขอ จึงเปิดหน้าต่างของ TradingView ได้ตามการออกแบบ เซิร์ฟเวอร์ไม่ลบและไม่เปลี่ยนชื่อสคริปต์ใด ๆ

ไม่มีเครื่องมือใดส่งคำสั่งซื้อขาย: บาร์รีเพลย์มีไว้เพื่อฝึกซ้อม และผู้ช่วยจะเก็บการเทรดฝึกซ้อมไว้ใน
บทสนทนาเท่านั้น ภาพหน้าจอจะส่งไปยังไคลเอนต์เป็นรูปภาพ และเซิร์ฟเวอร์ไม่เขียนภาพใดลงดิสก์
`ui_evaluate` ซึ่งรัน JavaScript ในหน้ากราฟ จะปิดอยู่ เว้นแต่คุณจะเริ่มเซิร์ฟเวอร์ด้วย `--allow-eval`
(`TV_MCP_ALLOW_EVAL=true`)

### <a id="tool-profiles"></a>โปรไฟล์เครื่องมือ

โดยค่าเริ่มต้น เซิร์ฟเวอร์จะเปิดให้ใช้เครื่องมือทั้งหมด 83 ตัว (`--profile full`) ไคลเอนต์บางตัวรับ
เครื่องมือได้จำนวนจำกัด (Cursor จะเตือนเมื่อเกิน 40) สำหรับไคลเอนต์เหล่านั้น `--profile core` จะให้
ชุดเครื่องมือจำเป็นที่ลดลงเหลือ 40 ตัว และ `--profile readonly` จะให้เฉพาะเครื่องมือ 37 ตัวที่อ่านอย่าง
เดียว `--tools` รับรูปแบบชื่อ เช่น `chart_*,data_*` และจำกัดโปรไฟล์ให้แคบลงอีก: เครื่องมือต้องอยู่ใน
โปรไฟล์และตรงกับรูปแบบ ดังนั้น `--profile core --tools 'pine_*'` ก็ยังไม่รวม `pine_open` และ
`pine_save` ซึ่งไม่ใช่เครื่องมือ core ส่วนเมื่อใช้โปรไฟล์ค่าเริ่มต้น `--tools` เพียงอย่างเดียวจะเป็นตัวกำหนด
เครื่องมือ คำอธิบายและคำแนะนำบางส่วนอ้างถึงเครื่องมือที่ `core` ไม่รวมไว้ เช่น `pine_open` และ
`pine_save` ซึ่งผู้ช่วยเรียกใช้ไม่ได้ภายใต้ `core` รีซอร์สจะเป็นไปตามเครื่องมือ: แต่ละรีซอร์สจะเปิดให้ใช้
ก็ต่อเมื่อมีเครื่องมือที่ใช้ข้อมูลร่วมกันเท่านั้น เช่น `tradingview://pine/source` กับ
`pine_get_source` ดังนั้น `--tools 'chart_*'` จะให้สถานะกราฟ แต่ไม่ให้อะไรจาก Pine Editor เลย

[เอกสารอ้างอิงเครื่องมือ](../tools.md) แสดงเครื่องมือทุกตัวพร้อมอินพุตและโปรไฟล์ที่เครื่องมือนั้นสังกัดอยู่

[docs/troubleshooting.md](../troubleshooting.md) อธิบายรหัสข้อผิดพลาดแต่ละรายการ และสิ่งที่ต้องทำ
เมื่อหา TradingView ไม่พบ พอร์ตดีบักถูกใช้งานอยู่ ไคลเอนต์ไม่แสดงเครื่องมือ หรือทันเนลปฏิเสธคำขอ

## <a id="dashboard"></a>แดชบอร์ด

เซิร์ฟเวอร์มาพร้อมเว็บแดชบอร์ดสำหรับดูว่าผู้ช่วยของคุณทำอะไรอยู่ และสำหรับลองรันเครื่องมือด้วยตนเอง
ไม่ต้องติดตั้งเพิ่ม: แพ็กเกจที่เผยแพร่มีแดชบอร์ดอยู่แล้ว และ `pnpm build` จะบิลด์แดชบอร์ดรวมเข้ากับ
เซิร์ฟเวอร์ในโค้ดที่เช็กเอาต์มา

![หน้าสถานะ: TradingView เข้าถึงได้ พบกราฟ และแอปพร้อมใช้งาน ข้อมูลของเซิร์ฟเวอร์ และขีดจำกัดของแผน](../images/dashboard-status.png)

### <a id="open-it"></a>เปิดแดชบอร์ด

- **ทรานสปอร์ต HTTP:** เริ่มเซิร์ฟเวอร์พร้อมโทเค็นแล้วเปิด `http://127.0.0.1:8787/` ในโหมดนี้
  แดชบอร์ดจะเปิดอยู่โดยค่าเริ่มต้น ส่วน `--no-dashboard` (`TV_MCP_DASHBOARD=false`) จะปิดแดชบอร์ด

  ```sh
  TV_MCP_AUTH_TOKEN="$(openssl rand -hex 32)" npx -y tradingview-desktop-mcp --transport http
  ```

  หากใช้โค้ดที่เช็กเอาต์มา ให้รัน `node packages/server/dist/cli.js --transport http` แทน

- **ควบคู่กับ stdio:** ไคลเอนต์ MCP ที่เริ่มเซิร์ฟเวอร์ผ่าน stdio ก็มีแดชบอร์ดได้เช่นกัน เพิ่ม
  `--dashboard` (`TV_MCP_DASHBOARD=true`) และ `TV_MCP_AUTH_TOKEN` ลงในการตั้งค่าของไคลเอนต์
  แดชบอร์ดจะรอรับการเชื่อมต่อที่ที่อยู่ของตัวเอง คือ `127.0.0.1:8787` เว้นแต่คุณจะตั้ง `--host` และ
  `--port` และจะไม่ให้บริการ `/mcp` หากไม่มีโทเค็น หรือพอร์ตถูกใช้งานอยู่ แดชบอร์ดจะปิดอยู่และ
  เซิร์ฟเวอร์จะบันทึกคำเตือน แต่เซิร์ฟเวอร์ MCP ยังทำงานต่อไป การเรียกที่ไคลเอนต์ทำจะปรากฏในล็อก
  แบบเรียลไทม์

เซิร์ฟเวอร์จะพิมพ์ที่อยู่ของแดชบอร์ดออกทาง stderr เมื่อเริ่มทำงาน และจะไม่พิมพ์โทเค็นออกมาเลย

### <a id="the-token"></a>โทเค็น

หน้าเว็บจะขอโทเค็น (`TV_MCP_AUTH_TOKEN`) ก่อนแสดงสิ่งใด ให้วางโทเค็นลงไป หรือเปิด
`http://127.0.0.1:8787/#token=<token>` หนึ่งครั้ง: หน้าเว็บจะอ่านโทเค็นจาก fragment แล้วลบออกจาก
ที่อยู่ และ fragment จะไม่ถูกส่งไปยังเซิร์ฟเวอร์ หน้าเว็บเก็บโทเค็นไว้ใน `sessionStorage` โทเค็นจึงหายไป
เมื่อคุณปิดแท็บ และหน้าเว็บจะส่งโทเค็นในรูปแบบ `Authorization: Bearer <token>` เท่านั้น ไม่ส่งใน URL
เลย เมื่อเซิร์ฟเวอร์รีสตาร์ตด้วยโทเค็นอื่น หน้าเว็บจะขอโทเค็นอีกครั้ง ดู
[SECURITY.md](../../SECURITY.md#the-dashboard)

### <a id="what-it-shows"></a>สิ่งที่แสดง

![ล็อกแบบเรียลไทม์: ตารางการเรียกเครื่องมือ เรียงจากใหม่สุด พร้อมเวลา เครื่องมือ ต้นทาง สถานะ และระยะเวลา โดยมีช่องค้นหาและตัวกรองอยู่ด้านบน](../images/dashboard-log.png)

- **Status** แสดงว่าเข้าถึง TradingView ได้หรือไม่ (และวิธีเปิดแอปเมื่อเข้าถึงไม่ได้) เซิร์ฟเวอร์ทำงาน
  อย่างไร ขีดจำกัดของแผน และการเรียกล่าสุด
- **Log** สตรีมการเรียกเครื่องมือทุกครั้งที่เซิร์ฟเวอร์รัน ไม่ว่าไคลเอนต์ MCP หรือแดชบอร์ดจะเป็นผู้เรียก
  พร้อมตัวกรองตามชื่อเครื่องมือ การหยุดชั่วคราว การล้าง และรายละเอียดของการเรียกแต่ละครั้ง เมื่อการ
  เชื่อมต่อหลุด จะแสดง "Reconnecting…" และทำงานต่อจากจุดที่หยุดไว้ แท็บแดชบอร์ดที่เปิดอยู่แต่ละแท็บ
  จะใช้สตรีมเหตุการณ์หนึ่งสตรีมกับเซิร์ฟเวอร์ และเบราว์เซอร์อนุญาตการเชื่อมต่อไปยังโฮสต์เดียวได้ประมาณหก
  การเชื่อมต่อ ดังนั้นหากเปิดแท็บแดชบอร์ดไว้หลายแท็บ แท็บใหม่อาจต้องรอการเชื่อมต่อที่ว่าง: ให้ปิดแท็บ
  ที่ไม่ได้ใช้
- **Tools** แสดงรายการเครื่องมือที่เซิร์ฟเวอร์มีให้พร้อมอินพุต และรันเครื่องมือด้วยตนเองได้ทีละตัว
  ผลลัพธ์จะแสดงตามที่ได้รับกลับมา โดย JSON ที่ยาวจะถูกยุบไว้หลัง "Show all" และรูปภาพจะแสดงเป็นรูปภาพ

![หน้าเครื่องมือ: รายการเครื่องมือพร้อมช่องค้นหาและตัวกรองทางซ้าย และ chart_get_state พร้อมคำอธิบาย ข้อมูล และช่องอินพุตทางขวา](../images/dashboard-tools.png)

การรันจากแดชบอร์ดคือการเรียกเครื่องมือจริง ซึ่งผ่านรีจิสทรีเดียวกับการเรียกผ่าน MCP จึงใช้สคีมา โปรไฟล์
กฎ `confirm` และการตรวจสอบขีดจำกัดของแผนเหมือนกัน และจะปรากฏในล็อกด้วย แดชบอร์ดจะขอให้คุณยืนยัน
ก่อนรันเครื่องมือใดก็ตามที่ไม่ใช่แบบอ่านอย่างเดียว

### <a id="the-api"></a>API

หน้าเว็บสื่อสารกับเซิร์ฟเวอร์ผ่าน API ขนาดเล็ก ซึ่งคุณเรียกเองได้ด้วย `curl` และโทเค็น ทุกเส้นทาง
ต้องใช้ `Authorization: Bearer <token>` และเซิร์ฟเวอร์จะตรวจสอบ `Host` และ `Origin` เช่นเดียวกับ
ที่ทำกับ `/mcp`

| เส้นทาง                  | หน้าที่                                                                    |
| ------------------------ | -------------------------------------------------------------------------- |
| `GET /api/info`          | เวอร์ชัน ทรานสปอร์ต โปรไฟล์ จำนวนเครื่องมือ และเวลาที่เริ่มทำงาน           |
| `GET /api/health`        | รายงานสุขภาพ: เข้าถึง TradingView ได้หรือไม่                               |
| `GET /api/tools`         | เครื่องมือที่มีให้ใช้ พร้อมสคีมาและแอนโนเทชัน                              |
| `POST /api/tools/<name>` | รันเครื่องมือด้วย `{"arguments": {...}}` โดยมีต้นทางเป็น `dashboard`       |
| `GET /api/events`        | Server-sent events ของการเรียกเครื่องมือ; `?limit=` กำหนดจำนวนที่จะเล่นซ้ำ |

ไฟล์ของหน้าเว็บเองที่ `/` ไม่ต้องใช้โทเค็นและไม่มีข้อมูลใด ๆ
