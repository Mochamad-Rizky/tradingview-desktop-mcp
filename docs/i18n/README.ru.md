[MCP](https://modelcontextprotocol.io)-сервер, который позволяет ИИ-ассистентам читать и управлять
приложением TradingView Desktop на вашем собственном компьютере. Он управляет приложением, в котором
вы уже вошли в аккаунт, по Chrome DevTools Protocol через отладочный порт, который приложение
открывает при запуске с `--remote-debugging-port`. Сервер автоматизирует только локальное приложение:
он не входит в аккаунт за вас, не обходит ограничения тарифа и не обращается к серверам TradingView.

> **Статус: до 1.0.** Названия инструментов и параметры могут измениться до версии 1.0. Установите
> пакет из npm, как описано ниже, или запустите сервер [из исходников](#quick-start-from-source). Он
> проверен на macOS; Windows и Linux поддерживаются по мере возможности.

Сервер предоставляет инструменты приложения (запуск, состояние, обнаружение, состояние интерфейса,
ограничения тарифа, переподключение), инструменты графика (состояние, символ, таймфрейм, тип графика,
видимый диапазон, прокрутка), инструменты рыночных данных (бары, котировки, информация о символе и
поиск), инструменты индикаторов (список, поиск, добавление, удаление, входные параметры, видимость,
значения), инструменты Pine Script (редактор и сохранённые скрипты, компиляция, умная компиляция с
исправлениями на основе правил, офлайн-анализ, консоль, а также линии, метки, прямоугольники и
таблицы, которые рисуют скрипты), инструменты Strategy Tester (результаты, сделки, кривая капитала),
инструменты рисования, алертов и списков наблюдения, инструменты макетов, мультиграфиков и вкладок,
bar replay, скриншоты, низкоуровневые инструменты интерфейса (клик, наведение, ввод текста, клавиши,
прокрутка, поиск, панели, полноэкранный режим и JavaScript на странице графика, если вы это
разрешите) и `batch_run`, который запускает несколько инструментов за один вызов. Кроме того, он
предоставляет ресурсы (состояние приложения, состояние графика и бары, исходный код Pine и результат
последней компиляции, отчёт по стратегии, активный список наблюдения) — каждый вместе с инструментом,
с которым он делит данные, — и пять промптов для типовых задач. Веб-панель показывает вызовы в
реальном времени и позволяет запускать инструменты вручную (см. [Панель](#dashboard)).

## <a id="install-by-asking-your-ai-app"></a>Установка через ваше ИИ-приложение

Вам не нужно вводить команды самостоятельно. Если ваше ИИ-приложение умеет запускать команды на вашем
компьютере, как Claude Code, Cursor, VS Code, Windsurf, Gemini CLI и Codex CLI, оно может выполнить
настройку за вас. Сначала:

1. Установите [TradingView Desktop](https://www.tradingview.com/desktop/) и войдите в аккаунт.
2. Установите [Node.js](https://nodejs.org) (LTS-версию), если его ещё нет.

Затем скопируйте этот промпт, вставьте его в ИИ-приложение и отправьте:

```text
Установи для меня MCP-сервер TradingView. Это npm-пакет tradingview-desktop-mcp
(https://github.com/Mochamad-Rizky/tradingview-desktop-mcp). Выполни следующие шаги и объясни
мне каждый из них простыми словами:

1. Проверь, что установлен Node.js 20.19 или новее. Если нет, остановись и расскажи, как его
   установить.
2. Выполни "npx -y tradingview-desktop-mcp config <client>", где <client> — приложение, в котором
   ты работаешь (claude-code, cursor, vscode, windsurf, gemini-cli или codex-cli). Сделай то, что
   выведет команда, чтобы добавить сервер в мою конфигурацию, и сохрани все серверы, которые там
   уже есть.
3. Запусти TradingView командой "npx -y tradingview-desktop-mcp launch". Если она сообщит, что
   TradingView уже запущен без отладочного порта, сначала спроси меня и только после моего согласия
   запусти её снова с --restart, потому что это закроет TradingView и я могу потерять несохранённые
   изменения.
4. Выполни "npx -y tradingview-desktop-mcp doctor" и скажи, все ли проверки пройдены. Если не
   прошла проверка графика, скажи мне вывести вкладку с графиком на передний план в TradingView.
5. Скажи, нужно ли мне перезапустить тебя или открыть новый чат, чтобы появились инструменты
   TradingView.
```

Когда всё будет готово, перезапустите приложение или откройте новый чат, если вас об этом попросили,
и спросите: «Проверь, что TradingView подключён». Затем попробуйте [промпты ниже](#try-these-prompts).

Пользуетесь Claude Desktop? Он не умеет запускать команды, но Claude Code, Cursor и другие
приложения из списка выше могут настроить его за вас: добавьте в конец промпта «Настрой это для
Claude Desktop (config claude-desktop), а не для этого приложения». ChatGPT и OpenAI API требуют
туннеля, который настраивается вручную (см.
[Удалённые клиенты и туннели](#remote-clients-and-tunnels)). Если ассистент застрянет, выполните
шаги ниже самостоятельно.

## <a id="install"></a>Установка

Вам понадобятся:

- TradingView Desktop, установленный и с выполненным входом в аккаунт.
- Node.js 20.19 или новее, который предоставляет `npx`.

Больше ничего не устанавливается: клиенты ниже запускают сервер командой `npx -y tradingview-desktop-mcp`,
которая скачивает пакет при первом использовании. Запустите TradingView с отладочным портом. Команда
`launch` находит приложение и запускает его именно так:

```sh
npx -y tradingview-desktop-mcp launch
```

TradingView допускает только один экземпляр. Если он уже запущен без отладочного порта, `launch`
останавливается и сообщает об этом; `launch --restart` корректно закрывает приложение и запускает его
снова с портом, при этом TradingView может сначала попросить сохранить изменения. Проверьте, что
сервер видит приложение:

```sh
npx -y tradingview-desktop-mcp doctor
```

`doctor` не проходит проверку графика, пока вкладка с графиком находится в фоне — за страницей «Новая
вкладка» или другой вкладкой без графика, поэтому выведите вкладку с графиком на передний план.
`npx -y tradingview-desktop-mcp --help` выводит список параметров, а [.env.example](../../.env.example) —
переменные окружения.

## <a id="connect-your-ai-app"></a>Подключение ИИ-приложения

`config <client>` выводит фрагмент конфигурации клиента и сообщает, куда его поместить. Каждое
руководство ниже содержит тот же фрагмент, шаги для конкретного приложения и что делать, если не
работает.

| Клиент                                         | Вывести фрагмент                                       |
| ---------------------------------------------- | ------------------------------------------------------ |
| [Claude Desktop](../clients/claude-desktop.md) | `npx -y tradingview-desktop-mcp config claude-desktop` |
| [Claude Code](../clients/claude-code.md)       | `npx -y tradingview-desktop-mcp config claude-code`    |
| [Cursor](../clients/cursor.md)                 | `npx -y tradingview-desktop-mcp config cursor`         |
| [VS Code](../clients/vscode.md)                | `npx -y tradingview-desktop-mcp config vscode`         |
| [Windsurf](../clients/windsurf.md)             | `npx -y tradingview-desktop-mcp config windsurf`       |
| [Gemini CLI](../clients/gemini-cli.md)         | `npx -y tradingview-desktop-mcp config gemini-cli`     |
| [Codex CLI](../clients/codex-cli.md)           | `npx -y tradingview-desktop-mcp config codex-cli`      |
| [ChatGPT](../clients/chatgpt.md)               | `npx -y tradingview-desktop-mcp config chatgpt`        |
| [OpenAI API](../clients/openai-api.md)         | `npx -y tradingview-desktop-mcp config openai-api`     |

Транспорт по умолчанию — stdio: stdout передаёт только сообщения MCP, а логи идут в stderr. Первые
семь клиентов запускают сервер сами. В Windows клиенту, который не может запустить `npx` напрямую,
нужна форма `cmd /c npx`; `config` выводит её при запуске в Windows (или с `--platform win32`).
`--profile` передаёт серверу [профиль инструментов](#tool-profiles).

### <a id="remote-clients-and-tunnels"></a>Удалённые клиенты и туннели

ChatGPT и OpenAI API не могут запустить программу на вашем компьютере. Они обращаются к серверу по
публичному HTTPS-адресу, поэтому вы запускаете его по HTTP и ставите перед ним туннель. Так в
интернете оказывается сервер, способный управлять вашим TradingView, в котором выполнен вход:
используйте `--profile readonly`, надёжный токен (`TV_MCP_AUTH_TOKEN`), публичный хост туннеля в
`--allowed-hosts` (`TV_MCP_ALLOWED_HOSTS`) и `--no-dashboard`, чтобы файлы панели не раздавались через
туннель. Руководства для [ChatGPT](../clients/chatgpt.md) и
[OpenAI API](../clients/openai-api.md) описывают это по шагам, а
[SECURITY.md](../../SECURITY.md#tunnels-and-remote-clients) перечисляет, к чему всё ещё имеет доступ токен
только для чтения.

## <a id="quick-start-from-source"></a>Быстрый старт из исходников

Чтобы запустить рабочую копию репозитория вместо опубликованного пакета, для сборки сервера нужен
Node.js 24 (`nvm use` читает `.nvmrc`) и [pnpm](https://pnpm.io), версия которого закреплена в
`package.json`. Собранный сервер работает на Node.js 20.19 или новее.

```sh
git clone https://github.com/Mochamad-Rizky/tradingview-desktop-mcp.git
cd tradingview-desktop-mcp
pnpm install && pnpm build
node packages/server/dist/cli.js launch
node packages/server/dist/cli.js doctor
```

`node packages/server/dist/cli.js config <client> --local` выводит фрагмент клиента для этой рабочей
копии, где вместо `npx` указаны `node` и абсолютный путь к `cli.js`. Для клиента с JSON-конфигурацией
запись выглядит так:

```json
{
  "mcpServers": {
    "tradingview": {
      "command": "node",
      "args": ["/absolute/path/to/tradingview-desktop-mcp/packages/server/dist/cli.js"]
    }
  }
}
```

Есть также HTTP-транспорт (`--transport http`); прежде чем им пользоваться, прочитайте
[SECURITY.md](../../SECURITY.md).

## <a id="use-it"></a>Использование

Подключите MCP-клиент, как описано выше, запустите TradingView с отладочным портом и попросите то,
что вам нужно, обычными словами. Ассистент сам выбирает и вызывает инструменты, поэтому знать их
названия не нужно. [Справочник по инструментам](../tools.md) перечисляет каждый инструмент с его
входными параметрами и профилями, в которые он входит.

### <a id="try-these-prompts"></a>Попробуйте эти промпты

Каждый промпт ниже — один из примеров в [docs/examples.md](../examples.md), где показаны вызовы
инструментов, которые делает ассистент, и их результаты: списки длиннее трёх элементов сокращены,
длительность каждого вызова (`durationMs`) опущена, а скриншот вместо показа упомянут в примечании.
Фрагменты — это строки этих результатов, а `…` отмечает места, где опущены строки других частей
результата. Значения синтетические: они получены от фиктивного приложения TradingView с вымышленным
графиком NASDAQ:AAPL, поэтому ничто здесь не является рыночными данными и ничто не взято из аккаунта;
у результатов та же структура, что выдаёт сервер, хотя отчёт Strategy Tester, на котором основан
пример с бэктестом, пока не считывался из настоящего приложения.

**«Что у меня на графике? Назови символ, таймфрейм и какие индикаторы на нём есть».** Ассистент
читает график с помощью `chart_get_state`
([подробнее](../examples.md#1-read-the-chart)):

```json
"symbol": "NASDAQ:AAPL",
"resolution": "1D",
"chartTypeName": "candles",
```

**«Покажи последние 3 дневные свечи».** Он читает бары с помощью `data_get_ohlcv`
([подробнее](../examples.md#3-read-the-last-candles)):

```json
"timeIso": "2024-10-27T00:00:00Z",
"open": 103.58,
"close": 103.42,
```

**«Добавь MACD на мой график».** На графике, где уже столько индикаторов, сколько позволяет тариф,
`indicator_add` ничего не добавляет и сообщает об ограничении, а удаление одного из ваших индикаторов,
чтобы освободить место, требует вашего подтверждения
([подробнее](../examples.md#5-add-an-indicator-to-a-full-chart)):

```json
"code": "PLAN_LIMIT",
"message": "The chart holds as many indicators as the plan allows (2)",
```

**«Напиши индикатор на Pine Script, который рисует 9- и 21-периодные скользящие средние цены
закрытия, и проверь, что он компилируется».** Он помещает скрипт в Pine Editor с помощью `pine_new`
и компилирует его с помощью `pine_compile`
([подробнее](../examples.md#6-write-and-compile-a-pine-script)):

```json
"success": true,
"errors": [],
"warnings": [],
```

**«Скрипт в моём Pine Editor не компилируется. Можешь исправить?»** `pine_smart_compile` компилирует
скрипт, применяет исправления на основе правил для известных ему ошибок, например имён Pine v4 в
скрипте на v6, и компилирует снова, не изменяя редактор
([подробнее](../examples.md#7-fix-a-pine-script-with-smart-compile)):

```json
"message": "Could not find function or function reference 'study'",
…
"applied": ["Replace study( with indicator(", "Replace rsi( with ta.rsi("]
…
"writtenBack": false
```

**«Как стратегия на моём графике показала себя в бэктесте?»** Он читает Strategy Tester с помощью
`strategy_get_results` и `strategy_get_trades`
([подробнее](../examples.md#8-read-backtest-results)):

```json
"netProfit": 155,
"totalTrades": 3,
"percentProfitable": 66.67,
"profitFactor": 4.1,
```

**«Нарисуй линию поддержки на уровне 102.80 на моём графике».** Он рисует горизонтальную линию с
помощью `drawing_create`, а `drawing_list` показывает её рядом с вашими собственными рисунками с
пометкой, что она нарисована этой сессией
([подробнее](../examples.md#9-draw-a-support-line)):

```json
"id": "DRW001",
"shape": "horizontal_line",
"text": "Support",
"createdByServer": true
```

**«Сообщи мне, когда Apple пересечёт 110».** `alert_create` создаёт ценовой алерт в вашем аккаунте
TradingView ([подробнее](../examples.md#10-create-a-price-alert)). Если в тарифе уже столько
алертов, сколько он позволяет, инструмент ничего не создаёт и сообщает об ограничении, а
`alert_list` показывает алерты, которые занимают лимит
([подробнее](../examples.md#11-create-an-alert-when-the-plan-is-full)):

```json
"symbol": "NASDAQ:AAPL",
"condition": "crossing",
"price": 110,
"expirationIso": "2024-11-26T00:00:00Z"
```

**«Добавь эти символы в мой список наблюдения: NYSE:IBM, FX:EURUSD, NASDAQ:MSFT и NASDAQ:MSTF».**
`watchlist_add_bulk` проверяет каждый символ через поиск символов TradingView, добавляет новые и
объясняет, почему пропустил остальные ([подробнее](../examples.md#12-add-symbols-to-a-watchlist)):

```json
"added": ["NYSE:IBM", "FX:EURUSD"],
…
{ "symbol": "NASDAQ:MSFT", "reason": "already_listed" },
{ "symbol": "NASDAQ:MSTF", "reason": "unknown" }
```

**«Дай мне потренироваться на bar replay моего графика с 2024-06-03: перейди на пять баров вперёд,
скажи, где мы находимся, затем заверши replay».** Он запускает bar replay с помощью `replay_start`,
делает шаги с помощью `replay_step`, читает текущую позицию replay с помощью `replay_status` и выходит
из него с помощью `replay_stop`. Никакой торговли: ни один инструмент не выставляет ордера
([подробнее](../examples.md#13-practice-with-bar-replay)):

```json
"dateIso": "2024-06-07T00:00:00Z",
"stepped": 5,
…
"position": null,
"realizedPL": null
```

**«Сделай скриншот моего графика».** `screenshot_capture` передаёт картинку ассистенту как
изображение вместе с её размером и ничего не записывает на диск
([подробнее](../examples.md#14-take-a-screenshot)):

```json
"data": { "target": "chart", "format": "jpeg", "width": 1180, "height": 640, "bytes": 3100 },
"meta": { "via": "cdp", "warnings": [] }
```

Сервер также предлагает пять собственных промптов, которые клиент с поддержкой MCP-промптов
показывает вам на выбор: `analyze_current_chart`, `multi_timeframe_review`,
`write_and_backtest_strategy`, `debug_pine_script` и `replay_practice_session`. Каждый из них
говорит ассистенту, какие инструменты вызывать, в каком порядке и о чём отчитаться.
`replay_practice_session` проводит тренировочную сессию на bar replay: ассистент проходит по истории
бар за баром, на каждом шаге спрашивает, открыли бы вы лонг, шорт или остались бы вне рынка, ведёт
журнал этих гипотетических сделок по ценам, которые считывает с графика, и подсчитывает их прибыль или
убыток. Сначала он проверяет, не запущен ли ваш собственный replay, и, прежде чем что-либо менять,
спрашивает, что с ним делать; в конце он останавливает тот replay, который запустил сам, и никогда —
ваш.

### <a id="safety"></a>Безопасность

Инструменты, которые изменяют ваш график, скрипты или аккаунт, бережно относятся к тому, что уже
принадлежит вам. Замена несохранённого текста в Pine Editor (кроме несохранённой правки, которую там
сделала сама эта сессия сервера), сохранение новой версии скрипта, созданного не этой сессией, и
удаление индикатора, который уже был на вашем графике, требуют `confirm: true`, и ассистент должен
передавать его только после вашего согласия. То же касается удаления рисунка, алерта, символа из
списка наблюдения или вкладки, которые эта сессия не создавала, не добавляла и не открывала, удаления
всех рисунков графика, переключения с макета с несохранёнными изменениями и перехода на макет
мультиграфика с меньшим числом графиков, чем показывает вкладка, — при следующем сохранении остальные
графики пропали бы. Ограничение тарифа, например на число индикаторов на графике, сохранённых
скриптов, алертов или графиков в макете, проверяется до того, как что-либо будет добавлено, и
сообщается как ошибка `PLAN_LIMIT` с указанием лимита; если в вашей сборке TradingView лимит
прочитать не удаётся, инструмент ничего не делает и сообщает об этом. Сервер не обходит ограничения.
Инструменты заранее проверяют, что заставило бы TradingView открыть окно с предложением перейти на
другой тариф или другое собственное диалоговое окно, и вместо этого отказываются выполнять действие,
но остаётся несколько окон, которые эти проверки предвидеть не могут: `layout_switch` может
столкнуться с предложением сменить тариф для сохранённого макета мультиграфика на тарифе с меньшим
числом графиков, для макета, который сервер TradingView отклоняет как превышающий лимит, и для
макета, который собственный список TradingView помечает как превышающий лимит, а `layout_list` — нет;
`layout_new` может получить сообщение TradingView, если тот отклонит новый макет уже после проверок; а `tab_close` может столкнуться с диалогом «Close tab?» для страницы, которая сообщает, есть ли в её
макете несохранённые изменения, дольше, чем TradingView готов ждать, или сообщает об идущей записи.
Низкоуровневые инструменты `ui_*` кликают и вводят то, что вы просите, поэтому по своей природе могут
открывать диалоговые окна TradingView. Сервер не удаляет и не переименовывает ни одного скрипта.

Ни один инструмент не выставляет ордера: bar replay предназначен для тренировки, и ассистент хранит
тренировочные сделки в разговоре. Скриншоты передаются клиенту как изображения, и сервер ни одного из
них не записывает на диск. `ui_evaluate`, который выполняет JavaScript на странице графика, выключен,
пока вы не запустите сервер с `--allow-eval` (`TV_MCP_ALLOW_EVAL=true`).

### <a id="tool-profiles"></a>Профили инструментов

По умолчанию сервер предоставляет все свои 83 инструмента (`--profile full`). Некоторые клиенты
принимают лишь ограниченное число инструментов (Cursor предупреждает, если их больше 40). Для них
`--profile core` предоставляет сокращённый набор из 40 основных инструментов, а `--profile readonly`
— только 37 инструментов, которые читают данные. `--tools` принимает шаблоны имён, например
`chart_*,data_*`, и ещё сильнее сужает профиль: инструмент должен входить в профиль и соответствовать
шаблону, поэтому `--profile core --tools 'pine_*'` всё равно не включает `pine_open` и `pine_save`,
которые не входят в core; с профилем по умолчанию инструменты выбирает один только `--tools`.
Некоторые описания и подсказки упоминают инструменты, которых нет в `core`, например `pine_open` и
`pine_save`; при `core` ассистент вызвать их не может. Ресурсы следуют за инструментами: каждый
предоставляется только вместе с инструментом, с которым он делит данные, например
`tradingview://pine/source` вместе с `pine_get_source`, поэтому `--tools 'chart_*'` даёт состояние
графика и ничего из Pine Editor.

[Справочник по инструментам](../tools.md) перечисляет каждый инструмент с его входными параметрами и
профилями, в которые он входит.

## <a id="dashboard"></a>Панель

В комплекте с сервером идёт веб-панель, где можно следить за действиями ассистента и вручную
попробовать инструмент. Отдельная установка не нужна: панель входит в опубликованный пакет, а
`pnpm build` встраивает её в сервер рабочей копии.

![Страница состояния: TradingView доступен, график найден, приложение готово; сведения о сервере и ограничения тарифа](../images/dashboard-status.png)

### <a id="open-it"></a>Как открыть

- **HTTP-транспорт:** запустите сервер с токеном и откройте `http://127.0.0.1:8787/`. В этом режиме
  панель включена по умолчанию; `--no-dashboard` (`TV_MCP_DASHBOARD=false`) её выключает.

  ```sh
  TV_MCP_AUTH_TOKEN="$(openssl rand -hex 32)" npx -y tradingview-desktop-mcp --transport http
  ```

  Из рабочей копии вместо этого выполните `node packages/server/dist/cli.js --transport http`.

- **Вместе со stdio:** MCP-клиент, который запускает сервер по stdio, тоже может получить панель.
  Добавьте `--dashboard` (`TV_MCP_DASHBOARD=true`) и `TV_MCP_AUTH_TOKEN` в его конфигурацию. Панель
  слушает свой собственный адрес — `127.0.0.1:8787`, если вы не задали `--host` и `--port`, — и не
  обслуживает `/mcp`. Без токена или если порт занят панель остаётся выключенной, а сервер пишет в лог
  предупреждение, но MCP-сервер продолжает работать. Вызовы, которые делает клиент, появляются в
  живом логе.

При запуске сервер выводит адрес панели в stderr. Токен он не выводит никогда.

### <a id="the-token"></a>Токен

Прежде чем что-либо показать, страница запрашивает токен (`TV_MCP_AUTH_TOKEN`). Вставьте его или один
раз откройте `http://127.0.0.1:8787/#token=<token>`: страница считает токен из фрагмента и уберёт его
из адреса, а сам фрагмент никогда не отправляется на сервер. Страница хранит токен в
`sessionStorage`, поэтому он исчезает, когда вы закрываете вкладку, и отправляет его только как
`Authorization: Bearer <token>`, никогда в URL. Если сервер перезапускается с другим токеном, страница
запрашивает его снова. См. [SECURITY.md](../../SECURITY.md#the-dashboard).

### <a id="what-it-shows"></a>Что она показывает

![Живой лог: таблица вызовов инструментов, новые сверху, с временем, инструментом, источником, статусом и длительностью, а над ней поиск и фильтры](../images/dashboard-log.png)

- **Status** показывает, доступен ли TradingView (и как его запустить, если нет), как работает
  сервер, ограничения тарифа и последние вызовы.
- **Log** в реальном времени показывает каждый вызов инструмента, который выполняет сервер, — сделан
  ли он MCP-клиентом или панелью, — с фильтром по имени инструмента, паузой, очисткой и подробностями
  каждого вызова. После обрыва соединения он показывает «Reconnecting…» и продолжает с того места, где
  остановился. Каждая открытая вкладка панели держит один поток событий к серверу, а браузер допускает
  около шести соединений к одному хосту, поэтому при большом числе открытых вкладок панели новая может
  ждать свободного соединения: закройте вкладки, которыми не пользуетесь.
- **Tools** перечисляет инструменты, которые предоставляет сервер, с их входными параметрами и
  позволяет запустить любой из них вручную. Результат показывается в том виде, в каком пришёл: длинный
  JSON свёрнут под «Show all», а изображения показываются как изображения.

![Страница инструментов: слева список инструментов с поиском и фильтрами, справа chart_get_state с описанием, сведениями и полями ввода](../images/dashboard-tools.png)

Запуск из панели — это настоящий вызов инструмента. Он проходит через тот же реестр, что и
MCP-вызов, поэтому действуют те же схемы, профиль, правила `confirm` и проверки ограничений тарифа, и
он появляется в логе. Перед запуском любого инструмента, который не только читает данные, панель
просит подтверждения.

### <a id="the-api"></a>API

Страница общается с сервером через небольшой API, который вы тоже можете вызывать с помощью `curl` и
токена. Каждый маршрут требует `Authorization: Bearer <token>`, а сервер проверяет `Host` и `Origin`
так же, как для `/mcp`.

| Маршрут                  | Что делает                                                                      |
| ------------------------ | ------------------------------------------------------------------------------- |
| `GET /api/info`          | Версия, транспорт, профиль, число инструментов и время запуска                  |
| `GET /api/health`        | Отчёт о состоянии: доступен ли TradingView                                      |
| `GET /api/tools`         | Доступные инструменты с их схемами и аннотациями                                |
| `POST /api/tools/<name>` | Запускает инструмент с `{"arguments": {...}}` от имени источника `dashboard`    |
| `GET /api/events`        | Server-sent events с вызовами инструментов; `?limit=` задаёт, сколько повторить |

Файлы самой страницы, по адресу `/`, не требуют токена и не содержат данных.
