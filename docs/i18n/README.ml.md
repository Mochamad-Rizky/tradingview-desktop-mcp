നിങ്ങളുടെ സ്വന്തം കമ്പ്യൂട്ടറിലെ TradingView Desktop ആപ്പ് വായിക്കാനും നിയന്ത്രിക്കാനും AI
അസിസ്റ്റന്റുകളെ അനുവദിക്കുന്ന ഒരു [MCP](https://modelcontextprotocol.io) സെർവറാണിത്. നിങ്ങൾ ഇതിനകം
ലോഗിൻ ചെയ്തിട്ടുള്ള ആപ്പിനെ ഇത് Chrome DevTools Protocol വഴി പ്രവർത്തിപ്പിക്കുന്നു; ആപ്പ്
`--remote-debugging-port` ഉപയോഗിച്ച് ആരംഭിക്കുമ്പോൾ തുറക്കുന്ന ഡീബഗ് പോർട്ട് വഴിയാണ് ഇത്. ഇത്
ലോക്കൽ ആപ്പിനെ മാത്രമേ ഓട്ടോമേറ്റ് ചെയ്യുന്നുള്ളൂ: നിങ്ങൾക്കുവേണ്ടി ലോഗിൻ ചെയ്യുകയോ, പ്ലാൻ
പരിധികൾ മറികടക്കുകയോ, TradingView-യുടെ സെർവറുകളെ വിളിക്കുകയോ ചെയ്യുന്നില്ല.

> **സ്ഥിതി: 1.0-ന് മുമ്പുള്ളത്.** 1.0-ന് മുമ്പ് ടൂളുകളുടെ പേരുകളും ഓപ്ഷനുകളും മാറിയേക്കാം. താഴെ
> കാണിച്ചിരിക്കുന്നതുപോലെ npm-ൽ നിന്ന് പാക്കേജ് ഇൻസ്റ്റാൾ ചെയ്യുക, അല്ലെങ്കിൽ സെർവർ
> [സോഴ്സിൽ നിന്ന്](#quick-start-from-source) പ്രവർത്തിപ്പിക്കുക. ഇത് macOS-ൽ പരീക്ഷിച്ചിട്ടുണ്ട്;
> Windows-ലും Linux-ലും പിന്തുണ കഴിയുന്നത്ര മാത്രം.

സെർവർ നൽകുന്ന ടൂളുകൾ ഇവയാണ്: ആപ്പ് ടൂളുകൾ (ലോഞ്ച്, ഹെൽത്ത്, കണ്ടെത്തൽ, ഇന്റർഫേസ് നില, പ്ലാൻ
പരിധികൾ, വീണ്ടും കണക്റ്റ് ചെയ്യൽ), ചാർട്ട് ടൂളുകൾ (നില, സിംബൽ, ടൈംഫ്രെയിം, ചാർട്ട് തരം, ദൃശ്യമായ
പരിധി, സ്ക്രോളിംഗ്), മാർക്കറ്റ് ഡാറ്റ ടൂളുകൾ (ബാറുകൾ, ക്വോട്ടുകൾ, സിംബൽ വിവരങ്ങളും തിരയലും),
ഇൻഡിക്കേറ്റർ ടൂളുകൾ (ലിസ്റ്റ്, തിരയൽ, ചേർക്കൽ, നീക്കംചെയ്യൽ, ഇൻപുട്ടുകൾ, ദൃശ്യത, മൂല്യങ്ങൾ),
Pine Script ടൂളുകൾ (എഡിറ്ററും സേവ് ചെയ്ത സ്ക്രിപ്റ്റുകളും, കംപൈൽ, നിയമാധിഷ്ഠിത തിരുത്തലുകളോടെയുള്ള
സ്മാർട്ട് കംപൈൽ, ഓഫ്‌ലൈൻ വിശകലനം, കൺസോൾ, സ്ക്രിപ്റ്റുകൾ വരയ്ക്കുന്ന ലൈനുകൾ, ലേബലുകൾ, ബോക്സുകൾ,
ടേബിളുകൾ), Strategy Tester ടൂളുകൾ (ഫലങ്ങൾ, ട്രേഡുകൾ, ഇക്വിറ്റി), ഡ്രോയിംഗ്, അലേർട്ട്, വാച്ച്‌ലിസ്റ്റ്
ടൂളുകൾ, ലേഔട്ട്, മൾട്ടി-ചാർട്ട്, ടാബ് ടൂളുകൾ, ബാർ റീപ്ലേ, സ്ക്രീൻഷോട്ടുകൾ, ലോ-ലെവൽ ഇന്റർഫേസ്
ടൂളുകൾ (ക്ലിക്ക്, ഹോവർ, ടൈപ്പ്, കീകൾ, സ്ക്രോൾ, കണ്ടെത്തൽ, പാനലുകൾ, ഫുൾസ്ക്രീൻ, നിങ്ങൾ
അനുവദിക്കുമ്പോൾ ചാർട്ട് പേജിൽ JavaScript), കൂടാതെ ഒരൊറ്റ കോളിൽ നിരവധി ടൂളുകൾ പ്രവർത്തിപ്പിക്കുന്ന
`batch_run`. ഇത് റിസോഴ്സുകളും നൽകുന്നു (ആപ്പിന്റെ ഹെൽത്ത്, ചാർട്ടിന്റെ നിലയും ബാറുകളും, Pine
സോഴ്സും അവസാന കംപൈൽ ഫലവും, സ്ട്രാറ്റജി റിപ്പോർട്ട്, സജീവ വാച്ച്‌ലിസ്റ്റ്); ഓരോന്നും അതിന്റെ ഡാറ്റ
പങ്കിടുന്ന ടൂളിനൊപ്പമാണ് ലഭിക്കുക. സാധാരണ ജോലികൾക്കായി അഞ്ച് പ്രോംപ്റ്റുകളും ഉണ്ട്. ഒരു വെബ്
ഡാഷ്ബോർഡ് കോളുകൾ തത്സമയം കാണിക്കുകയും ടൂളുകൾ കൈകൊണ്ട് പ്രവർത്തിപ്പിക്കുകയും ചെയ്യുന്നു
(കാണുക: [ഡാഷ്ബോർഡ്](#dashboard)).

## <a id="install-by-asking-your-ai-app"></a>നിങ്ങളുടെ AI ആപ്പിനോട് ആവശ്യപ്പെട്ട് ഇൻസ്റ്റാൾ ചെയ്യുക

നിങ്ങൾ സ്വയം ഒരു കമാൻഡും ടൈപ്പ് ചെയ്യേണ്ടതില്ല. Claude Code, Cursor, VS Code, Windsurf, Gemini CLI,
Codex CLI എന്നിവയെപ്പോലെ നിങ്ങളുടെ AI ആപ്പിന് നിങ്ങളുടെ കമ്പ്യൂട്ടറിൽ കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കാൻ
കഴിയുമെങ്കിൽ, അതിന് നിങ്ങൾക്കുവേണ്ടി സെറ്റപ്പ് ചെയ്യാനാകും. ആദ്യം:

1. [TradingView Desktop](https://www.tradingview.com/desktop/) ഇൻസ്റ്റാൾ ചെയ്ത് ലോഗിൻ ചെയ്യുക.
2. ഇതുവരെ ഇല്ലെങ്കിൽ, [Node.js](https://nodejs.org) (LTS പതിപ്പ്) ഇൻസ്റ്റാൾ ചെയ്യുക.

തുടർന്ന് ഈ പ്രോംപ്റ്റ് കോപ്പി ചെയ്ത്, നിങ്ങളുടെ AI ആപ്പിൽ പേസ്റ്റ് ചെയ്ത് അയയ്ക്കുക:

```text
എനിക്കുവേണ്ടി TradingView MCP സെർവർ ഇൻസ്റ്റാൾ ചെയ്യുക. ഇത് npm പാക്കേജ് tradingview-desktop-mcp ആണ്
(https://github.com/Mochamad-Rizky/tradingview-desktop-mcp). ഈ ഘട്ടങ്ങൾ പിന്തുടരുക, ഓരോന്നും
ലളിതമായ വാക്കുകളിൽ മലയാളത്തിൽ എനിക്ക് വിശദീകരിച്ചുതരിക:

1. Node.js 20.19 അല്ലെങ്കിൽ അതിനു ശേഷമുള്ള പതിപ്പ് ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടോ എന്ന് പരിശോധിക്കുക.
   ഇല്ലെങ്കിൽ, നിർത്തി അത് എങ്ങനെ ഇൻസ്റ്റാൾ ചെയ്യാമെന്ന് എന്നോട് പറയുക.
2. "npx -y tradingview-desktop-mcp config <client>" പ്രവർത്തിപ്പിക്കുക; ഇവിടെ <client> എന്നത് നീ
   പ്രവർത്തിക്കുന്ന ആപ്പാണ് (claude-code, cursor, vscode, windsurf, gemini-cli അല്ലെങ്കിൽ
   codex-cli). എന്റെ കോൺഫിഗറേഷനിൽ സെർവർ ചേർക്കാൻ അത് പ്രിന്റ് ചെയ്യുന്നത് ചെയ്യുക, അവിടെ ഇതിനകം
   ഉള്ള മറ്റ് സെർവറുകൾ നിലനിർത്തുക.
3. "npx -y tradingview-desktop-mcp launch" ഉപയോഗിച്ച് TradingView ആരംഭിക്കുക. ഡീബഗ് പോർട്ട്
   ഇല്ലാതെ TradingView ഇതിനകം പ്രവർത്തിക്കുന്നുണ്ടെന്ന് അത് പറഞ്ഞാൽ, ആദ്യം എന്നോട് ചോദിക്കുക,
   ഞാൻ സമ്മതിച്ചാൽ മാത്രം --restart ഉപയോഗിച്ച് വീണ്ടും പ്രവർത്തിപ്പിക്കുക, കാരണം അത് TradingView
   അടയ്ക്കും, സേവ് ചെയ്യാത്ത മാറ്റങ്ങൾ എനിക്ക് നഷ്ടപ്പെട്ടേക്കാം.
4. "npx -y tradingview-desktop-mcp doctor" പ്രവർത്തിപ്പിച്ച് എല്ലാ പരിശോധനകളും വിജയിച്ചോ എന്ന്
   എന്നോട് പറയുക. ചാർട്ട് പരിശോധന പരാജയപ്പെട്ടാൽ, TradingView-ൽ ചാർട്ട് ടാബ് മുന്നിലേക്ക്
   കൊണ്ടുവരാൻ എന്നോട് പറയുക.
5. TradingView ടൂളുകൾ കാണാൻ നിന്നെ റീസ്റ്റാർട്ട് ചെയ്യണോ, അതോ പുതിയ ചാറ്റ് തുറക്കണോ എന്ന് എന്നോട്
   പറയുക.
```

അത് പൂർത്തിയാകുമ്പോൾ, ആവശ്യപ്പെട്ടിട്ടുണ്ടെങ്കിൽ ആപ്പ് റീസ്റ്റാർട്ട് ചെയ്യുകയോ പുതിയ ചാറ്റ്
തുറക്കുകയോ ചെയ്യുക, എന്നിട്ട് "TradingView കണക്റ്റ് ആയിട്ടുണ്ടോ എന്ന് പരിശോധിക്കുക." എന്ന്
ചോദിക്കുക. തുടർന്ന് [താഴെയുള്ള പ്രോംപ്റ്റുകൾ](#try-these-prompts) പരീക്ഷിക്കുക.

Claude Desktop ആണോ ഉപയോഗിക്കുന്നത്? അതിന് കമാൻഡുകൾ പ്രവർത്തിപ്പിക്കാൻ കഴിയില്ല, പക്ഷേ Claude Code,
Cursor, മുകളിലുള്ള മറ്റ് ആപ്പുകൾ എന്നിവയ്ക്ക് നിങ്ങൾക്കുവേണ്ടി അത് സജ്ജമാക്കാനാകും: പ്രോംപ്റ്റിന്റെ
അവസാനം "ഈ ആപ്പിനല്ല, Claude Desktop-നായി സജ്ജമാക്കുക (config claude-desktop)." എന്ന് ചേർക്കുക.
ChatGPT-ക്കും OpenAI API-ക്കും ഒരു ടണൽ ആവശ്യമാണ്, അത് നിങ്ങൾ കൈകൊണ്ട് സജ്ജമാക്കണം
(കാണുക: [റിമോട്ട് ക്ലയന്റുകളും ടണലുകളും](#remote-clients-and-tunnels)). അസിസ്റ്റന്റ് കുടുങ്ങിയാൽ,
താഴെയുള്ള ഘട്ടങ്ങൾ സ്വയം പിന്തുടരുക.

## <a id="install"></a>ഇൻസ്റ്റാൾ

നിങ്ങൾക്ക് വേണ്ടത്:

- TradingView Desktop, ഇൻസ്റ്റാൾ ചെയ്ത് ലോഗിൻ ചെയ്തത്.
- `npx` നൽകുന്ന Node.js 20.19 അല്ലെങ്കിൽ അതിനു ശേഷമുള്ള പതിപ്പ്.

മറ്റൊന്നും ഇൻസ്റ്റാൾ ചെയ്യുന്നില്ല: താഴെയുള്ള ക്ലയന്റുകൾ `npx -y tradingview-desktop-mcp`
ഉപയോഗിച്ചാണ് സെർവർ ആരംഭിക്കുന്നത്, ആദ്യ ഉപയോഗത്തിൽ ഇത് പാക്കേജ് ഡൗൺലോഡ് ചെയ്യുന്നു. TradingView
അതിന്റെ ഡീബഗ് പോർട്ടോടെ ആരംഭിക്കുക. `launch` കമാൻഡ് ആപ്പ് കണ്ടെത്തി അങ്ങനെ ആരംഭിക്കുന്നു:

```sh
npx -y tradingview-desktop-mcp launch
```

TradingView ഒരു ഇൻസ്റ്റൻസ് മാത്രമേ അനുവദിക്കുന്നുള്ളൂ. ഡീബഗ് പോർട്ട് ഇല്ലാതെ അത് ഇതിനകം
പ്രവർത്തിക്കുന്നുണ്ടെങ്കിൽ, `launch` നിർത്തി അക്കാര്യം പറയുന്നു; `launch --restart` അതിനെ മര്യാദയോടെ
അടച്ച് പോർട്ടോടെ വീണ്ടും ആരംഭിക്കുന്നു, അതിനുമുമ്പ് മാറ്റങ്ങൾ സേവ് ചെയ്യാൻ TradingView
ആവശ്യപ്പെട്ടേക്കാം. സെർവറിന് ആപ്പിൽ എത്താൻ കഴിയുന്നുണ്ടോ എന്ന് പരിശോധിക്കുക:

```sh
npx -y tradingview-desktop-mcp doctor
```

ചാർട്ട് ടാബ് പശ്ചാത്തലത്തിൽ, New tab പേജിനോ ചാർട്ടില്ലാത്ത മറ്റൊരു ടാബിനോ പിന്നിലായിരിക്കുമ്പോൾ
`doctor` അതിന്റെ ചാർട്ട് പരിശോധനയിൽ പരാജയപ്പെടുന്നു, അതിനാൽ ചാർട്ട് ടാബ് മുന്നിലേക്ക് കൊണ്ടുവരിക.
`npx -y tradingview-desktop-mcp --help` ഓപ്ഷനുകൾ ലിസ്റ്റ് ചെയ്യുന്നു, [.env.example](../../.env.example)
എൻവയോൺമെന്റ് വേരിയബിളുകളും.

## <a id="connect-your-ai-app"></a>നിങ്ങളുടെ AI ആപ്പ് കണക്റ്റ് ചെയ്യുക

`config <client>` ഒരു ക്ലയന്റിന്റെ കോൺഫിഗറേഷൻ സ്നിപ്പെറ്റ് പ്രിന്റ് ചെയ്യുകയും അത് എവിടെ ചേർക്കണമെന്ന്
പറയുകയും ചെയ്യുന്നു. താഴെയുള്ള ഓരോ ട്യൂട്ടോറിയലിലും അതേ സ്നിപ്പെറ്റും, ആ ആപ്പിനുള്ള ഘട്ടങ്ങളും,
പ്രവർത്തിക്കാത്തപ്പോൾ എന്തുചെയ്യണമെന്നും ഉണ്ട്.

| ക്ലയന്റ്                                       | സ്നിപ്പെറ്റ് പ്രിന്റ് ചെയ്യുക                          |
| ---------------------------------------------- | ------------------------------------------------------ |
| [Claude Desktop](../clients/claude-desktop.md) | `npx -y tradingview-desktop-mcp config claude-desktop` |
| [Claude Code](../clients/claude-code.md)       | `npx -y tradingview-desktop-mcp config claude-code`    |
| [Cursor](../clients/cursor.md)                 | `npx -y tradingview-desktop-mcp config cursor`         |
| [VS Code](../clients/vscode.md)                | `npx -y tradingview-desktop-mcp config vscode`         |
| [Windsurf](../clients/windsurf.md)             | `npx -y tradingview-desktop-mcp config windsurf`       |
| [Gemini CLI](../clients/gemini-cli.md)         | `npx -y tradingview-desktop-mcp config gemini-cli`     |
| [Codex CLI](../clients/codex-cli.md)           | `npx -y tradingview-desktop-mcp config codex-cli`      |
| [ChatGPT](../clients/chatgpt.md)               | `npx -y tradingview-desktop-mcp config chatgpt`        |
| [OpenAI API](../clients/openai-api.md)         | `npx -y tradingview-desktop-mcp config openai-api`     |

ഡിഫോൾട്ട് ട്രാൻസ്പോർട്ട് stdio ആണ്; ഇതിൽ stdout MCP സന്ദേശങ്ങൾ മാത്രം വഹിക്കുന്നു, ലോഗുകൾ
stderr-ലേക്ക് പോകുന്നു. ആദ്യത്തെ ഏഴ് ക്ലയന്റുകൾ സെർവർ സ്വയം ആരംഭിക്കുന്നു. Windows-ൽ, `npx` നേരിട്ട്
ആരംഭിക്കാൻ കഴിയാത്ത ഒരു ക്ലയന്റിന് `cmd /c npx` രൂപം ആവശ്യമാണ്; Windows-ൽ പ്രവർത്തിക്കുമ്പോൾ (അല്ലെങ്കിൽ
`--platform win32` ഉപയോഗിക്കുമ്പോൾ) `config` അത് പ്രിന്റ് ചെയ്യുന്നു. `--profile` ഒരു
[ടൂൾ പ്രൊഫൈൽ](#tool-profiles) സെർവറിലേക്ക് കൈമാറുന്നു.

### <a id="remote-clients-and-tunnels"></a>റിമോട്ട് ക്ലയന്റുകളും ടണലുകളും

ChatGPT-ക്കും OpenAI API-ക്കും നിങ്ങളുടെ കമ്പ്യൂട്ടറിൽ ഒരു പ്രോഗ്രാം ആരംഭിക്കാൻ കഴിയില്ല. അവ ഒരു
പബ്ലിക് HTTPS വിലാസത്തിലാണ് സെർവറിൽ എത്തുന്നത്, അതിനാൽ നിങ്ങൾ അത് HTTP വഴി പ്രവർത്തിപ്പിച്ച് അതിനു
മുന്നിൽ ഒരു ടണൽ വയ്ക്കുന്നു. ഇതോടെ, ലോഗിൻ ചെയ്ത നിങ്ങളുടെ TradingView നിയന്ത്രിക്കാൻ കഴിയുന്ന ഒരു
സെർവർ ഇന്റർനെറ്റിൽ എത്തുന്നു: `--profile readonly`, ശക്തമായ ഒരു ടോക്കൺ (`TV_MCP_AUTH_TOKEN`),
`--allowed-hosts`-ൽ (`TV_MCP_ALLOWED_HOSTS`) ടണലിന്റെ പബ്ലിക് ഹോസ്റ്റ്, ഡാഷ്ബോർഡിന്റെ ഫയലുകൾ ടണൽ
വഴി സെർവ് ചെയ്യപ്പെടാതിരിക്കാൻ `--no-dashboard` എന്നിവ ഉപയോഗിക്കുക.
[ChatGPT](../clients/chatgpt.md), [OpenAI API](../clients/openai-api.md) എന്നിവയ്ക്കുള്ള
ട്യൂട്ടോറിയലുകൾ ഇത് ഘട്ടം ഘട്ടമായി വിശദീകരിക്കുന്നു, ഒരു റീഡ്-ഒൺലി ടോക്കണിന് ഇപ്പോഴും എന്തിലെല്ലാം
എത്താൻ കഴിയുമെന്ന് [SECURITY.md](../../SECURITY.md#tunnels-and-remote-clients) ലിസ്റ്റ് ചെയ്യുന്നു.

## <a id="quick-start-from-source"></a>സോഴ്സിൽ നിന്ന് ക്വിക്ക് സ്റ്റാർട്ട്

പ്രസിദ്ധീകരിച്ച പാക്കേജിനു പകരം ഒരു ചെക്കൗട്ട് പ്രവർത്തിപ്പിക്കാൻ, സെർവർ ബിൽഡ് ചെയ്യാൻ Node.js 24
(`nvm use` `.nvmrc` വായിക്കുന്നു), [pnpm](https://pnpm.io) എന്നിവ വേണം; pnpm-ന്റെ പതിപ്പ്
`package.json` നിശ്ചയിക്കുന്നു. ബിൽഡ് ചെയ്ത സെർവർ Node.js 20.19-ലോ അതിനു ശേഷമുള്ള പതിപ്പിലോ
പ്രവർത്തിക്കുന്നു.

```sh
git clone https://github.com/Mochamad-Rizky/tradingview-desktop-mcp.git
cd tradingview-desktop-mcp
pnpm install && pnpm build
node packages/server/dist/cli.js launch
node packages/server/dist/cli.js doctor
```

`node packages/server/dist/cli.js config <client> --local` ഈ ചെക്കൗട്ടിനായി ഒരു ക്ലയന്റിന്റെ
സ്നിപ്പെറ്റ് പ്രിന്റ് ചെയ്യുന്നു, `npx`-ന്റെ സ്ഥാനത്ത് `node`-ഉം `cli.js`-ന്റെ പൂർണ്ണ പാത്തും ഉപയോഗിച്ച്.
JSON കോൺഫിഗറേഷനുള്ള ഒരു ക്ലയന്റിന്, എൻട്രി ഇങ്ങനെയായിരിക്കും:

```json
{
  "mcpServers": {
    "tradingview": {
      "command": "node",
      "args": ["/absolute/path/to/tradingview-desktop-mcp/packages/server/dist/cli.js"]
    }
  }
}
```

ഒരു HTTP ട്രാൻസ്പോർട്ടും (`--transport http`) ഉണ്ട്; അത് ഉപയോഗിക്കുന്നതിനുമുമ്പ്
[SECURITY.md](../../SECURITY.md) വായിക്കുക.

## <a id="use-it"></a>ഉപയോഗിക്കുക

TradingView അതിന്റെ ഡീബഗ് പോർട്ടോടെ പ്രവർത്തിക്കുന്ന നിലയിൽ, മുകളിൽ വിവരിച്ചതുപോലെ ഒരു MCP ക്ലയന്റ്
കണക്റ്റ് ചെയ്യുക, എന്നിട്ട് നിങ്ങൾക്ക് വേണ്ടത് ലളിതമായ വാക്കുകളിൽ ചോദിക്കുക. അസിസ്റ്റന്റ് ടൂളുകൾ
തിരഞ്ഞെടുത്ത് വിളിക്കുന്നു, അതിനാൽ അവയുടെ പേരുകൾ നിങ്ങൾ അറിയേണ്ടതില്ല.
[ടൂൾ റഫറൻസ്](../tools.md) ഓരോ ടൂളും അതിന്റെ ഇൻപുട്ടുകളും അത് ഉൾപ്പെടുന്ന പ്രൊഫൈലുകളും സഹിതം
ലിസ്റ്റ് ചെയ്യുന്നു.

### <a id="try-these-prompts"></a>ഈ പ്രോംപ്റ്റുകൾ പരീക്ഷിക്കുക

താഴെയുള്ള ഓരോ പ്രോംപ്റ്റും [docs/examples.md](../examples.md)-ലെ ഉദാഹരണങ്ങളിൽ ഒന്നാണ്; അസിസ്റ്റന്റ്
നടത്തുന്ന ടൂൾ കോളുകളും ഫലങ്ങളും അത് കാണിക്കുന്നു. അതിൽ മൂന്നിലധികം ഇനങ്ങളുള്ള ലിസ്റ്റുകൾ
ചുരുക്കിയിരിക്കുന്നു, ഓരോ കോളിന്റെയും ദൈർഘ്യം (`durationMs`) ഒഴിവാക്കിയിരിക്കുന്നു, സ്ക്രീൻഷോട്ട്
കാണിക്കുന്നതിനു പകരം ഒരു കുറിപ്പിൽ പരാമർശിച്ചിരിക്കുന്നു. ഭാഗങ്ങൾ ആ ഫലങ്ങളിലെ വരികളാണ്, ഒരു
ഫലത്തിന്റെ മറ്റ് ഭാഗങ്ങളിലെ വരികൾ ഒഴിവാക്കിയ സ്ഥലം `…` സൂചിപ്പിക്കുന്നു. മൂല്യങ്ങൾ കൃത്രിമമാണ്: ഒരു
സാങ്കൽപ്പിക NASDAQ:AAPL ചാർട്ടുള്ള വ്യാജ TradingView ആപ്പിൽ നിന്നാണ് അവ വരുന്നത്, അതിനാൽ ഒന്നും
മാർക്കറ്റ് ഡാറ്റയല്ല, ഒന്നും ഒരു അക്കൗണ്ടിൽ നിന്നുള്ളതുമല്ല; ഫലങ്ങൾക്ക് സെർവർ നൽകുന്ന ഘടന തന്നെയാണ്,
എന്നാൽ ബാക്ക്ടെസ്റ്റ് ഉദാഹരണത്തിനു പിന്നിലെ Strategy Tester റിപ്പോർട്ട് ഇതുവരെ യഥാർത്ഥ ആപ്പിൽ നിന്ന്
വായിച്ചിട്ടില്ല.

**"എന്റെ ചാർട്ടിൽ ഞാൻ എന്താണ് കാണുന്നത്? സിംബൽ, ടൈംഫ്രെയിം, അതിൽ ഏതെല്ലാം ഇൻഡിക്കേറ്ററുകൾ
ഉണ്ടെന്ന് പറയൂ."** അസിസ്റ്റന്റ് `chart_get_state` ഉപയോഗിച്ച് ചാർട്ട് വായിക്കുന്നു
([വിശദാംശങ്ങൾ](../examples.md#1-read-the-chart)):

```json
"symbol": "NASDAQ:AAPL",
"resolution": "1D",
```

### <a id="safety"></a>സുരക്ഷ

നിങ്ങളുടെ ചാർട്ടോ സ്ക്രിപ്റ്റുകളോ അക്കൗണ്ടോ മാറ്റുന്ന ടൂളുകൾ ഇതിനകം നിങ്ങളുടേതായവയുടെ കാര്യത്തിൽ
ശ്രദ്ധാലുക്കളാണ്. Pine Editor-ലെ സേവ് ചെയ്യാത്ത ടെക്സ്റ്റ് മാറ്റിസ്ഥാപിക്കൽ (സെർവറിന്റെ ഈ സെഷൻ തന്നെ
അവിടെ വരുത്തിയ സേവ് ചെയ്യാത്ത എഡിറ്റ് ഒഴികെ), ഈ സെഷൻ സൃഷ്ടിക്കാത്ത ഒരു സ്ക്രിപ്റ്റിന്റെ പുതിയ പതിപ്പ്
സേവ് ചെയ്യൽ, നിങ്ങളുടെ ചാർട്ടിൽ ഇതിനകം ഉണ്ടായിരുന്ന ഒരു ഇൻഡിക്കേറ്റർ നീക്കം ചെയ്യൽ എന്നിവയ്ക്കെല്ലാം
`confirm: true` ആവശ്യമാണ്; നിങ്ങൾ സമ്മതിച്ചതിനു ശേഷം മാത്രമേ അസിസ്റ്റന്റ് അത് നൽകാവൂ. ഈ സെഷൻ
സൃഷ്ടിക്കുകയോ ചേർക്കുകയോ തുറക്കുകയോ ചെയ്യാത്ത ഒരു ഡ്രോയിംഗ്, അലേർട്ട്, വാച്ച്‌ലിസ്റ്റ് സിംബൽ അല്ലെങ്കിൽ
ടാബ് നീക്കം ചെയ്യൽ, ഒരു ചാർട്ടിലെ എല്ലാ ഡ്രോയിംഗുകളും നീക്കം ചെയ്യൽ, സേവ് ചെയ്യാത്ത മാറ്റങ്ങളുള്ള ഒരു
ലേഔട്ടിൽ നിന്ന് മാറൽ, ടാബ് കാണിക്കുന്നതിനേക്കാൾ കുറച്ച് ചാർട്ടുകളുള്ള ഒരു മൾട്ടി-ചാർട്ട് ലേഔട്ടിലേക്ക്
മാറൽ (അതിന്റെ അടുത്ത സേവ് മറ്റുള്ളവ ഒഴിവാക്കും) എന്നിവയ്ക്കും ഇതുതന്നെ. ഒരു ചാർട്ടിലെ
ഇൻഡിക്കേറ്ററുകളുടെ, സേവ് ചെയ്ത സ്ക്രിപ്റ്റുകളുടെ, അലേർട്ടുകളുടെ അല്ലെങ്കിൽ ഒരു ലേഔട്ടിലെ ചാർട്ടുകളുടെ
എണ്ണം പോലുള്ള ഒരു പ്ലാൻ പരിധി, എന്തെങ്കിലും ചേർക്കുന്നതിനുമുമ്പ് പരിശോധിക്കുകയും പരിധിയോടൊപ്പം ഒരു
`PLAN_LIMIT` പിശകായി റിപ്പോർട്ട് ചെയ്യുകയും ചെയ്യുന്നു; നിങ്ങളുടെ TradingView ബിൽഡിൽ പരിധി വായിക്കാൻ
കഴിയാത്തപ്പോൾ, ടൂൾ ഒന്നും ചെയ്യാതെ അക്കാര്യം പറയുന്നു. സെർവർ ഒരു പരിധിയും മറികടക്കുന്നില്ല.
TradingView-യെ അതിന്റെ അപ്ഗ്രേഡ് ഡയലോഗോ സ്വന്തമായ മറ്റൊരു ഡയലോഗോ തുറക്കാൻ ഇടയാക്കുന്നത് എന്താണെന്ന്
ടൂളുകൾ ആദ്യം പരിശോധിച്ച്, പകരം നിരസിക്കുന്നു; എന്നാൽ ഈ പരിശോധനകൾക്ക് മുൻകൂട്ടി കാണാൻ കഴിയാത്ത ചില
പ്രോംപ്റ്റുകൾ ബാക്കിയുണ്ട്: കുറച്ച് ചാർട്ടുകളുള്ള ഒരു പ്ലാനിൽ സേവ് ചെയ്ത മൾട്ടി-ചാർട്ട് ലേഔട്ടിന്,
TradingView-യുടെ സെർവർ പരിധിക്കപ്പുറമെന്ന് നിരസിക്കുന്ന ലേഔട്ടിന്, TradingView സ്വന്തമായി സൂക്ഷിക്കുന്ന
ലിസ്റ്റ് പരിധിക്കു മുകളിലെന്ന് അടയാളപ്പെടുത്തുകയും `layout_list` അങ്ങനെ ചെയ്യാതിരിക്കുകയും ചെയ്യുന്ന
ലേഔട്ടിന് എന്നിവയ്ക്ക് `layout_switch` ഒരു അപ്ഗ്രേഡ് പ്രോംപ്റ്റ് നേരിട്ടേക്കാം; പരിശോധനകൾക്കു ശേഷം
TradingView പുതിയ ലേഔട്ട് നിരസിക്കുമ്പോൾ `layout_new` TradingView-യുടെ ഒരു സന്ദേശം നേരിട്ടേക്കാം;
അതിന്റെ ലേഔട്ടിൽ സേവ് ചെയ്യാത്ത മാറ്റങ്ങളുണ്ടോ എന്ന് പറയാൻ TradingView കാത്തിരിക്കുന്നതിനേക്കാൾ
കൂടുതൽ സമയമെടുക്കുന്ന, അല്ലെങ്കിൽ ഒരു റെക്കോർഡിംഗ് പുരോഗമിക്കുന്നതായി റിപ്പോർട്ട് ചെയ്യുന്ന ഒരു
പേജിന് `tab_close` "Close tab?" ഡയലോഗ് നേരിട്ടേക്കാം. ലോ-ലെവൽ `ui_*` ടൂളുകൾ നിങ്ങൾ ആവശ്യപ്പെടുന്നത്
ക്ലിക്ക് ചെയ്യുകയും ടൈപ്പ് ചെയ്യുകയും ചെയ്യുന്നു, അതിനാൽ രൂപകൽപ്പന പ്രകാരം തന്നെ അവയ്ക്ക് TradingView-യുടെ
ഡയലോഗുകൾ തുറക്കാനാകും. സെർവർ ഒരു സ്ക്രിപ്റ്റും ഡിലീറ്റ് ചെയ്യുകയോ പേരുമാറ്റുകയോ ചെയ്യുന്നില്ല.

ഒരു ടൂളും ഓർഡറുകൾ നൽകുന്നില്ല: ബാർ റീപ്ലേ പരിശീലനത്തിനുള്ളതാണ്, അസിസ്റ്റന്റ് പരിശീലന ട്രേഡുകൾ
സംഭാഷണത്തിനുള്ളിൽ മാത്രം സൂക്ഷിക്കുന്നു. സ്ക്രീൻഷോട്ടുകൾ ഇമേജുകളായി ക്ലയന്റിലേക്ക് പോകുന്നു, സെർവർ
ഒന്നും ഡിസ്കിലേക്ക് എഴുതുന്നില്ല. ചാർട്ട് പേജിൽ JavaScript പ്രവർത്തിപ്പിക്കുന്ന `ui_evaluate`,
`--allow-eval` (`TV_MCP_ALLOW_EVAL=true`) ഉപയോഗിച്ച് സെർവർ ആരംഭിക്കാത്തപക്ഷം ഓഫായിരിക്കും.

### <a id="tool-profiles"></a>ടൂൾ പ്രൊഫൈലുകൾ

ഡിഫോൾട്ടായി സെർവർ അതിന്റെ 83 ടൂളുകളും നൽകുന്നു (`--profile full`). ചില ക്ലയന്റുകൾ പരിമിതമായ എണ്ണം
ടൂളുകൾ മാത്രമേ സ്വീകരിക്കുന്നുള്ളൂ (40-ന് മുകളിൽ Cursor മുന്നറിയിപ്പ് നൽകുന്നു). അവയ്ക്കായി,
`--profile core` 40 അത്യാവശ്യ ടൂളുകളുടെ ചുരുക്കിയ ഒരു സെറ്റ് നൽകുന്നു, `--profile readonly` വായിക്കുന്ന
37 ടൂളുകൾ മാത്രം നൽകുന്നു. `--tools` `chart_*,data_*` പോലുള്ള പേര് പാറ്റേണുകൾ സ്വീകരിച്ച് പ്രൊഫൈൽ
കൂടുതൽ ചുരുക്കുന്നു: ഒരു ടൂൾ പ്രൊഫൈലിൽ ഉണ്ടായിരിക്കുകയും ഒരു പാറ്റേണുമായി പൊരുത്തപ്പെടുകയും വേണം,
അതിനാൽ `--profile core --tools 'pine_*'` ഇപ്പോഴും core ടൂളുകളല്ലാത്ത `pine_open`, `pine_save` എന്നിവ
ഒഴിവാക്കുന്നു; ഡിഫോൾട്ട് പ്രൊഫൈലിൽ, `--tools` മാത്രമായി ടൂളുകൾ തിരഞ്ഞെടുക്കുന്നു. ചില വിവരണങ്ങളും
സൂചനകളും `core` ഒഴിവാക്കുന്ന `pine_open`, `pine_save` പോലുള്ള ടൂളുകളെ പരാമർശിക്കുന്നു; `core`-ൽ
അസിസ്റ്റന്റിന് അവയെ വിളിക്കാൻ കഴിയില്ല. റിസോഴ്സുകൾ ടൂളുകളെ പിന്തുടരുന്നു: ഓരോന്നും അതിന്റെ ഡാറ്റ
പങ്കിടുന്ന ടൂളിനൊപ്പം മാത്രമേ ലഭ്യമാകൂ, ഉദാഹരണത്തിന് `pine_get_source`-നൊപ്പം
`tradingview://pine/source`; അതിനാൽ `--tools 'chart_*'` ചാർട്ടിന്റെ നില നൽകുന്നു, Pine Editor-ൽ
നിന്ന് ഒന്നും നൽകുന്നില്ല.

[ടൂൾ റഫറൻസ്](../tools.md) ഓരോ ടൂളും അതിന്റെ ഇൻപുട്ടുകളും അത് ഉൾപ്പെടുന്ന പ്രൊഫൈലുകളും സഹിതം
ലിസ്റ്റ് ചെയ്യുന്നു.

[docs/troubleshooting.md](../troubleshooting.md) ഓരോ പിശക് കോഡും വിശദീകരിക്കുന്നു, കൂടാതെ
TradingView കണ്ടെത്താനാകാത്തപ്പോഴും, ഡീബഗ് പോർട്ട് തിരക്കിലായിരിക്കുമ്പോഴും, ഒരു ക്ലയന്റ് ടൂളുകൾ

പ്രവർത്തിപ്പിക്കേണ്ടത് `npx -y tradingview-desktop-mcp doctor` ആണ്.

## <a id="dashboard"></a>ഡാഷ്ബോർഡ്

നിങ്ങളുടെ അസിസ്റ്റന്റ് എന്തുചെയ്യുന്നുവെന്ന് നിരീക്ഷിക്കാനും ഒരു ടൂൾ കൈകൊണ്ട് പരീക്ഷിക്കാനുമായി സെർവറിനൊപ്പം
ഒരു വെബ് ഡാഷ്ബോർഡ് വരുന്നു. ഇതിന് അധിക ഇൻസ്റ്റാൾ ആവശ്യമില്ല: പ്രസിദ്ധീകരിച്ച പാക്കേജിൽ ഇത്
ഉൾപ്പെടുന്നു, `pnpm build` ഒരു ചെക്കൗട്ടിന്റെ സെർവറിലേക്ക് ഇത് ബിൽഡ് ചെയ്യുന്നു.

![സ്റ്റാറ്റസ് പേജ്: TradingView-ൽ എത്താനാകുന്നു, ഒരു ചാർട്ട് കണ്ടെത്തി, ആപ്പ് തയ്യാർ, സെർവറിന്റെ വിവരങ്ങൾ, പ്ലാൻ പരിധികൾ](../images/dashboard-status.png)

### <a id="open-it"></a>ഇത് തുറക്കുക

- **HTTP ട്രാൻസ്പോർട്ട്:** ഒരു ടോക്കൺ ഉപയോഗിച്ച് സെർവർ ആരംഭിച്ച് `http://127.0.0.1:8787/` തുറക്കുക.
  ഈ മോഡിൽ ഡാഷ്ബോർഡ് ഡിഫോൾട്ടായി ഓണാണ്; `--no-dashboard` (`TV_MCP_DASHBOARD=false`) അത് ഓഫാക്കുന്നു.

  ```sh
  TV_MCP_AUTH_TOKEN="$(openssl rand -hex 32)" npx -y tradingview-desktop-mcp --transport http
  ```

  ഒരു ചെക്കൗട്ടിൽ നിന്നാണെങ്കിൽ, പകരം `node packages/server/dist/cli.js --transport http`
  പ്രവർത്തിപ്പിക്കുക.

- **stdio-യോടൊപ്പം:** stdio വഴി സെർവർ ആരംഭിക്കുന്ന ഒരു MCP ക്ലയന്റിനും ഒരു ഡാഷ്ബോർഡ് ഉണ്ടാകാം.
  അതിന്റെ കോൺഫിഗറേഷനിൽ `--dashboard` (`TV_MCP_DASHBOARD=true`), `TV_MCP_AUTH_TOKEN` എന്നിവ ചേർക്കുക.
  ഡാഷ്ബോർഡ് അതിന്റെ സ്വന്തം വിലാസത്തിൽ കേൾക്കുന്നു, നിങ്ങൾ `--host`, `--port` എന്നിവ സജ്ജമാക്കിയില്ലെങ്കിൽ
  `127.0.0.1:8787`, കൂടാതെ `/mcp` സെർവ് ചെയ്യുന്നില്ല. ടോക്കൺ ഇല്ലെങ്കിൽ, അല്ലെങ്കിൽ പോർട്ട്
  ഉപയോഗത്തിലാണെങ്കിൽ, ഡാഷ്ബോർഡ് ഓഫായി തുടരുകയും സെർവർ ഒരു മുന്നറിയിപ്പ് ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു,
  എന്നാൽ MCP സെർവർ പ്രവർത്തനം തുടരുന്നു. ക്ലയന്റ് നടത്തുന്ന കോളുകൾ ലൈവ് ലോഗിൽ കാണിക്കുന്നു.

സെർവർ ആരംഭിക്കുമ്പോൾ ഡാഷ്ബോർഡിന്റെ വിലാസം stderr-ൽ പ്രിന്റ് ചെയ്യുന്നു. ടോക്കൺ ഒരിക്കലും പ്രിന്റ്
ചെയ്യുന്നില്ല.

### <a id="the-token"></a>ടോക്കൺ

എന്തെങ്കിലും കാണിക്കുന്നതിനുമുമ്പ് പേജ് ടോക്കൺ (`TV_MCP_AUTH_TOKEN`) ആവശ്യപ്പെടുന്നു. അത് പേസ്റ്റ്
ചെയ്യുക, അല്ലെങ്കിൽ `http://127.0.0.1:8787/#token=<token>` ഒരിക്കൽ തുറക്കുക: പേജ് ഫ്രാഗ്മെന്റിൽ നിന്ന്
ടോക്കൺ വായിച്ച് വിലാസത്തിൽ നിന്ന് നീക്കം ചെയ്യുന്നു, ഫ്രാഗ്മെന്റ് ഒരിക്കലും സെർവറിലേക്ക് അയയ്ക്കുന്നില്ല.
പേജ് ടോക്കൺ `sessionStorage`-ൽ സൂക്ഷിക്കുന്നു, അതിനാൽ ടാബ് അടയ്ക്കുമ്പോൾ അത് ഇല്ലാതാകുന്നു, കൂടാതെ
ടോക്കൺ `Authorization: Bearer <token>` ആയി മാത്രമേ അയയ്ക്കുന്നുള്ളൂ, ഒരിക്കലും URL-ൽ അല്ല. സെർവർ
മറ്റൊരു ടോക്കണുമായി റീസ്റ്റാർട്ട് ചെയ്യുമ്പോൾ, പേജ് വീണ്ടും ചോദിക്കുന്നു.
[SECURITY.md](../../SECURITY.md#the-dashboard) കാണുക.

  പ്രവർത്തിക്കുന്നുവെന്നും, പ്ലാൻ പരിധികളും, ഏറ്റവും പുതിയ കോളുകളും കാണിക്കുന്നു.
- **Log** സെർവർ പ്രവർത്തിപ്പിക്കുന്ന ഓരോ ടൂൾ കോളും, അത് ഒരു MCP ക്ലയന്റോ ഡാഷ്ബോർഡോ നടത്തിയതായാലും,
  തത്സമയം സ്ട്രീം ചെയ്യുന്നു; ടൂൾ പേര് അനുസരിച്ചുള്ള ഫിൽട്ടർ, പോസ്, ക്ലിയർ, ഓരോ കോളിന്റെയും
  വിശദാംശങ്ങൾ എന്നിവയോടെ. കണക്ഷൻ മുറിഞ്ഞാൽ അത് "Reconnecting…" എന്ന് കാണിച്ച് നിർത്തിയിടത്തു നിന്ന്
  തുടരുന്നു. ഡാഷ്ബോർഡിന്റെ ഓരോ തുറന്ന ടാബും സെർവറിലേക്ക് ഒരു ഇവന്റ് സ്ട്രീം നിലനിർത്തുന്നു, ഒരു
  ബ്രൗസർ ഒരു ഹോസ്റ്റിലേക്ക് ഏകദേശം ആറ് കണക്ഷനുകൾ മാത്രമേ അനുവദിക്കുന്നുള്ളൂ, അതിനാൽ നിരവധി ഡാഷ്ബോർഡ്
  ടാബുകൾ തുറന്നിരിക്കുമ്പോൾ ഒരു പുതിയ ടാബ് ഒഴിവുള്ള കണക്ഷനായി കാത്തിരുന്നേക്കാം: ഉപയോഗിക്കാത്ത ടാബുകൾ
  അടയ്ക്കുക.
- **Tools** സെർവർ നൽകുന്ന ടൂളുകൾ അവയുടെ ഇൻപുട്ടുകളോടെ ലിസ്റ്റ് ചെയ്യുകയും ഒന്ന് കൈകൊണ്ട്
  പ്രവർത്തിപ്പിക്കുകയും ചെയ്യുന്നു. ഫലം തിരികെ വന്നതുപോലെ തന്നെ കാണിക്കുന്നു; നീളമുള്ള JSON
  "Show all"-നു പിന്നിൽ ചുരുക്കിയും ഇമേജുകൾ ഇമേജുകളായും.

![ടൂൾസ് പേജ്: ഇടതുവശത്ത് തിരയലും ഫിൽട്ടറുകളുമുള്ള ടൂൾ ലിസ്റ്റ്, വലതുവശത്ത് chart_get_state അതിന്റെ വിവരണം, വിവരങ്ങൾ, ഇൻപുട്ട് ഫീൽഡുകൾ എന്നിവയോടൊപ്പം](../images/dashboard-tools.png)

ഡാഷ്ബോർഡിൽ നിന്നുള്ള ഒരു റൺ യഥാർത്ഥ ടൂൾ കോളാണ്. ഇത് ഒരു MCP കോളിന്റെ അതേ രജിസ്ട്രിയിലൂടെ
കടന്നുപോകുന്നു, അതിനാൽ അതേ സ്കീമകളും പ്രൊഫൈലും `confirm` നിയമങ്ങളും പ്ലാൻ പരിധി പരിശോധനകളും
ബാധകമാണ്, ഇത് ലോഗിൽ കാണിക്കുകയും ചെയ്യുന്നു. റീഡ്-ഒൺലി അല്ലാത്ത ഏതെങ്കിലും ടൂൾ
പ്രവർത്തിപ്പിക്കുന്നതിനുമുമ്പ് ഡാഷ്ബോർഡ് നിങ്ങളുടെ സ്ഥിരീകരണം ചോദിക്കുന്നു.

### <a id="the-api"></a>API

പേജ് ഒരു ചെറിയ API വഴിയാണ് സെർവറുമായി സംസാരിക്കുന്നത്; `curl`-ഉം ടോക്കണും ഉപയോഗിച്ച് നിങ്ങൾക്കും
അതിനെ വിളിക്കാം. ഓരോ റൂട്ടിനും `Authorization: Bearer <token>` ആവശ്യമാണ്, `/mcp`-ന് ചെയ്യുന്നതുപോലെ
സെർവർ `Host`, `Origin` എന്നിവ പരിശോധിക്കുന്നു.

| റൂട്ട്                   | ഇത് എന്തുചെയ്യുന്നു                                                                           |
| ------------------------ | --------------------------------------------------------------------------------------------- |
| `GET /api/info`          | പതിപ്പ്, ട്രാൻസ്പോർട്ട്, പ്രൊഫൈൽ, ടൂളുകളുടെ എണ്ണം, ആരംഭിച്ച സമയം                              |
| `GET /api/health`        | ഹെൽത്ത് റിപ്പോർട്ട്: TradingView-ൽ എത്താനാകുമോ എന്ന്                                          |
| `GET /api/tools`         | ലഭ്യമായ ടൂളുകൾ, അവയുടെ സ്കീമകളും അനോട്ടേഷനുകളും സഹിതം                                         |
| `POST /api/tools/<name>` | `{"arguments": {...}}` ഉപയോഗിച്ച്, `dashboard` ഉറവിടമായി, ഒരു ടൂൾ പ്രവർത്തിപ്പിക്കുന്നു       |
| `GET /api/events`        | ടൂൾ കോളുകളുടെ സെർവർ-സെന്റ് ഇവന്റുകൾ; എത്രയെണ്ണം റീപ്ലേ ചെയ്യണമെന്ന് `?limit=` നിശ്ചയിക്കുന്നു |

പേജിന്റെ സ്വന്തം ഫയലുകൾക്ക്, `/`-ൽ, ടോക്കൺ ആവശ്യമില്ല, അവയിൽ ഡാറ്റയൊന്നുമില്ല.
