# Usage examples

Each section below is a request that you can type to an AI assistant that has this server connected: the prompt, the tool calls that the assistant makes for it, what the server returns, and what the assistant can tell you from that. [The README](../README.md) shows how to connect a client.

> **All values on this page are synthetic.** The results come from running the real server against the fake TradingView app of the test suite, which serves a made-up NASDAQ:AAPL chart: prices from a seeded random walk, one bar for every calendar day (weekends included), an invented layout, invented drawings, alerts, watchlists and scripts, an invented strategy report, and a plain grey picture for a screenshot. Indicator values follow the closing prices instead of being calculated by the indicators. Nothing here is market data, and nothing comes from a real account. The shape of every result, with its field names, error codes and hints, is what the server returns, with one caveat: what the Strategy Tester holds for a strategy has not been read from the real app yet, so the shape of its report, behind the backtest results below, follows the reverse-engineering notes rather than an observed report.

Every result is the envelope of the server: `ok`, then `data` or `error`, then `meta`. `meta.durationMs` is left out, because it differs on every run, which leaves the `meta` of an error empty, and a list longer than three items is cut to its first three followed by a marker such as `"… 1 more"`. Text with line breaks, such as a script or a diff, is laid out again as lines below its block, and an image that comes in front of the envelope, such as a screenshot, is named in a note instead of shown. Two times that the server takes from the clock are fixed as well, as if the call had been made at the time of the last bar of the chart: the time of a compilation, and the expiration of an alert set without one.

This page is generated by `pnpm docs:examples` from the scenarios in `packages/server/scripts/docs/scenarios.ts`, and a test fails when it is out of date. Do not edit it by hand.


`source`:

```pine
//@version=6
indicator("RSI line")
plot(ta.rsi(close, 14))
```

`diff`:

```diff
@@ -1,3 +1,3 @@
 //@version=6
-study("RSI line")
-plot(rsi(close, 14))
+indicator("RSI line")
+plot(ta.rsi(close, 14))
```

**The assistant answers**

> The first attempt failed at line 2, column 1: the compiler could not find the function study, a name of Pine v4 in a script that says //@version=6, and stopped there. The rules know every such name, so two fixes were applied, study( became indicator( and rsi( became ta.rsi(, and the second attempt compiled (success is true). The diff shows what changed. The Pine Editor still holds your original text (writtenBack is false), and the assistant can write the fixed text into it if you want it there.
