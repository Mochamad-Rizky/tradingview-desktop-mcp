## App (6 tools)

### app_launch

**Launch TradingView**

`Destructive` `core`

Starts TradingView Desktop with its debug port open, which is how every other tool reaches it, and waits until a chart tab is up. Use it when app_health shows that the debug port does not answer. It does nothing when TradingView already answers on the port (status already-running), and fails with CDP_UNREACHABLE while another browser holds the port. TradingView allows only one instance, so when it runs without the debug port the call fails with RESTART_REQUIRED; to quit and reopen it, call again with restart: true and confirm: true. A restart closes TradingView, so unsaved edits, such as Pine Editor text, can be lost. A restart can take more than a minute (up to 20 s for the app to quit, then up to the launch timeout, 60 s by default, for it to come back), which may exceed the request timeout of some clients; a plain launch is quicker. Returns status (already-running, launched or restarted), executable (the file that was started, or null), endpoint (the debug port) and waitedMs.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `restart` | boolean | no | Set to true when TradingView runs without the debug port and has to be quit and reopened. It also needs confirm: true. Default false. |
| `port` | integer | no | Debug port to start TradingView on. Must equal the configured CDP port (TV_CDP_PORT); omit it normally. 1 to 65535. |
| `confirm` | boolean | no | Must be true together with restart: true, to confirm that TradingView may be closed and reopened, which loses unsaved edits such as Pine Editor text. Ignored without restart. |

### app_health

**TradingView health**

`Read-only` `Idempotent` `core` `readonly`

Reports how far TradingView is up, and changes nothing. cdp says whether the debug port answers (reachable), at which endpoint and in which browser; if cdp.reachable is false, TradingView is not running with the debug port: call app_launch. chart says how many chart tabs are open and the url of the one in use. app says whether the app in that tab is ready (it has its API and is connected to the data servers), whether it is connected, and when it was built. capabilities lists which parts of the page the other tools can use (the public API, the active chart, the chart model, the replay and Pine editor APIs, the module registry, the desktop bridge); every flag is false on a page whose app has not started, and capabilities is null when no chart tab could be read. It is a report, so it succeeds when TradingView is down. With several chart tabs open and none in front, chart.tabs is above 1 and a warning asks you to focus one TradingView tab. When the tab in front shows no chart, such as TradingView's New tab page, chart.inBackground is true and a warning names tab_switch. When another browser holds the debug port, cdp.reachable is false, cdp.otherBrowser is true and a warning says how to free it.

No inputs.

### app_discover

**Discover TradingView**

`Read-only` `Idempotent` `core` `readonly`

Finds TradingView on this machine without changing anything. Returns executable (the file app_launch would start, or null when TradingView is not installed or TV_APP_PATH is wrong), running (whether a TradingView process exists), cdpReachable (whether its debug port answers) and targets: every page the debug port lists, each with id, kind, title and url. kind is chart (a tab that shows a chart, the kind the other tools drive), window-chrome (the window with the tab strip), helper (a page the app keeps for itself), blank (a page without content) or other (a frame, a worker, or a page that is not a chart, such as the TradingView home page). Use it to find out why no chart tab is found, for example when the only tab is not on a chart. targets is empty, with a warning that says what to do, when the debug port does not answer.

No inputs.

### app_get_ui_state

**Read the interface state**

`Read-only` `Idempotent` `core` `readonly`

Reads which parts of the TradingView interface are open in the chart tab, and changes nothing. Returns rightPanel (open, and activeWidget: watchlist, alerts, object_tree, pine_logs, detail or null), panels (watchlist, alerts, object_tree, data_window and pine_editor, each true while its button in the right toolbar shows its panel; the data window is a tab of the panel of the object tree, so object_tree and data_window are never both true), bottomPanelOpen, dialogs (the dialogs, menus and popups that are open, each by its data-name, aria-label or role and never by its text, or unnamed when it has none), fullscreen, replayToolbarVisible and pineEditorOpen. Use it before clicking in the interface, to see whether a dialog covers the chart. It reads the page, so a part is reported as closed when the page does not show it. fullscreen is TradingView's own fullscreen mode, as the app reports it, which fills the tab with the chart and leaves the window as it is; it is also true while an element of the page is in the full screen of the browser, or while the fullscreen button says it is pressed, which TradingView was not seen to do. Where the app cannot say, fullscreen reads false unless one of those holds. Fails with NOT_AVAILABLE on a page without a DOM.

No inputs.

### app_get_plan_limits

**Read the plan limits**

`Read-only` `Idempotent` `readonly`

Reads what the TradingView plan of the signed-in account allows, and changes nothing. Returns limits: for each of INDICATORS_ON_CHART (indicators on one chart), SAVED_PINE_SCRIPTS, CHART_STORAGE, MULTIPLE_CHARTS (charts in one layout), SERVER_SIDE_ALERTS, WATCHLIST_SYMBOLS, STUDY_TEMPLATES and HISTORICAL_BARS, the number the app reports, or null when the app does not report one. The limits are those of the user's own plan, as the app reports them; 99999 means unlimited. Use it before adding indicators or saving scripts, to see how much room is left: the tools that act check the same limits and fail with PLAN_LIMIT instead of opening an upgrade dialog. It reads the modules the app has loaded, so every limit is null on a page whose app has not started.

No inputs.

### app_reconnect

**Reconnect to TradingView**

`Destructive` `core`

Drops every connection this server holds to TradingView, so that the next tool call connects again and picks the chart tab anew. Use it when calls keep failing after TradingView was restarted, a tab was replaced or the page was reloaded. With reloadTab: true it first asks TradingView Desktop to reload the chart tab, which also recovers a page that is stuck. That needs confirm: true as well, because reloading loses unsaved edits in the tab, such as Pine Editor text; without it nothing is reloaded and nothing is dropped. The page needs a few seconds to come back, so check app_health afterwards. It does not start TradingView: use app_launch for that. Returns reset (true) and reloadRequested.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `reloadTab` | boolean | no | Also reload the chart tab before the connections are dropped (default false). Use it only when the page is stuck: the tab loses unsaved edits, such as Pine Editor text. It also needs confirm: true. |
| `confirm` | boolean | no | Must be true together with reloadTab: true, to confirm that the chart tab may be reloaded, which loses unsaved edits such as Pine Editor text. Ignored without reloadTab. |

### chart_set_timeframe

**Change the chart timeframe**

`Idempotent` `core`

Changes the timeframe (interval) of a chart and waits until its data has loaded. ### chart_set_visible_range

**Change the visible range**

`Idempotent` `core`

Changes which period a chart shows. Give either from and to (the chart then shows the loaded bars nearest to them), or a preset of the date range bar under the chart, not both. A range is set through the time scale of the chart. | `to` | string or number | no | End of the range, with from: ISO 8601 date/time (e.g. 2024-01-31 or 2024-01-31T10:00:00Z) or Unix timestamp in seconds/milliseconds; compact forms like 20240131 are rejected. Without an offset a time is UTC. |

## Market data (5 tools)

### data_get_ohlcv

**Read OHLCV bars**

`Read-only` `Idempotent` `core` `readonly`

Reads the bars (open, high, low, close, volume) of the symbol and timeframe a chart shows: the last count bars, or the last count bars between from and to. When fewer bars are loaded, older history is loaded the way a scroll to the left loads it, as far as the app allows and the call timeout lets it. To read another symbol or timeframe, change the chart first (chart_set_symbol, chart_set_timeframe).

| `to` | string or number | no | Latest bar time to return: ISO 8601 date/time (e.g. 2024-01-31 or 2024-01-31T10:00:00Z) or Unix timestamp in seconds/milliseconds; compact forms like 20240131 are rejected. Without an offset a time is UTC. |

### pine_smart_compile

**Compile a Pine script and fix it**

`Destructive` `core`

Compiles a Pine script with the compiler of TradingView and, while it has errors, applies deterministic fixes and compiles again, at most maxAttempts compilations (1 to 5, default 3). The fixes are fixed rules and no AI model is involved: the Pine v4 names that v5 renamed or moved into a namespace (study to indicator, security to request.security, tostring to str.tostring, and sma, ema, rsi, macd, stoch, atr, crossover, crossunder, highest, lowest and change to ta.*) and a missing //@version=6, each applied where pine_analyze finds it or a compile error points at it, and only to a script of version 5 or later or without a version. The compilations share one time limit, that of one page call: each waits only for the time left, and when too little is left for another attempt the call stops there, applies no further fix and says so in a warning. Compile errors are a result; a failure of TradingView to compile at all is NOT_AVAILABLE or TIMEOUT. An editor with unsaved changes needs confirm: true: an open one is refused with CONFIRMATION_REQUIRED before anything is compiled, and a closed one that the write opens, and that restores unsaved text when it opens, is refused then, after the compilations; either way nothing is written. An unsaved edit this session made, the text it last wrote into the editor (with pine_new and a source, pine_set_source or the writeBack of pine_smart_compile), needs no confirm: true to be changed while the editor holds it exactly. Any other unsaved text needs it, the session's own too once TradingView kept it across a close of the editor. TradingView flags unsaved changes until the editor is closed, also after a call with confirm: true replaced them. When the text came from the editor, it is written back only if the editor still holds the same script and text when the write comes (checked in the page, right before it acts, whatever confirm says); else nothing is written, writtenBack is false, a warning says that the editor changed and the result is still returned. Nothing is saved or added to the chart. pine_get_errors returns the full result of the last compilation, warnings included.

| `applyFixes` | boolean | no | false to compile once and apply no fix. Default: true. |

## Bar replay (5 tools)

### replay_start

So is, with NOT_AVAILABLE, a target that a dialog, a menu, a popup or a frame covers, a point inside an open menu or dialog included (aim at its item by selector or text instead): the event would go to that, and what it is cannot be told. An element that only holds a trading control, such as the chart pane, can be scrolled. The pointer moves onto the target first, and the wheel turns only if the target still looks the same then. No button is pressed. NOT_AVAILABLE and INVALID_INPUT as for ui_click. Returns target, by (selector or point), point (where the wheel turned, in CSS pixels), deltaX and deltaY.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `selector` | string | no | A CSS selector: the first element that matches is the target, at the center of its box. Prefer stable attributes, an id, data-qa-id, data-name or aria-label, as ui_find_element gives them: the class names of TradingView change with every build. 1 to 1000 characters. |
| `x` | number | no | With y: the point to act at, in CSS pixels from the left edge of the visible part of the page, as ui_find_element reports rect. Rounded to whole pixels. A point outside the visible part is INVALID_INPUT. |
| `y` | number | no | With x: the point to act at, in CSS pixels from the top edge of the visible part of the page, as ui_find_element reports rect. Rounded to whole pixels. A point outside the visible part is INVALID_INPUT. |
| `deltaX` | number | no | How far to scroll to the right, in CSS pixels, from -10000 to 10000; below 0 scrolls to the left. Default 0. -10000 to 10000. |
| `deltaY` | number | yes | How far to scroll down, in CSS pixels, from -10000 to 10000; below 0 scrolls up. A notch of a mouse wheel is about 100. -10000 to 10000. |
| `target` | string | no | Which page to act on: chart (default) is the chart tab; window is the window chrome, the strip with the tabs of the app. One of: `chart`, `window`. |

### ui_find_element

**Find elements**

`Read-only` `Idempotent` `readonly`

Lists the visible elements of TradingView that match a CSS selector, have a name (text), or both, to aim ui_click, ui_hover and ui_scroll with. Changes nothing. text matches an element whose name equals it, the rule ui_click uses: a name is its aria-label, or else the value of an input button, or else the text it shows, with a space between the texts of different elements and white space collapsed (a label made of Sell and 100 in two spans is "Sell 100"), or else its title, compared whole and ignoring case. Each element has selector (one that picks it, by its id, data-qa-id, data-name or aria-label; null when none of those does), tag, role, name, text (at most 200 characters), rect (its box in CSS pixels from the top left of the visible part of the page, the x and y the other tools take), visible (always true: hidden elements are left out), unsafe (true for a trading control or anything inside one, which the other tools refuse) and holdsUnsafe (true for an element that holds one, which ui_click refuses, at a point on it too, while ui_hover and ui_scroll do not). ui_click also refuses an element named after a trading action (an aria-label, input button value, text shown or title of an element nothing else names that holds the word Buy or Sell; placing, submitting, sending, cancelling or modifying an order; closing, exiting, reversing or flattening a position; Close all, Flatten or Reverse, as words). What is typed into a field (an input, a text area, a select) or an editable region is never read: such an element comes without text, and its text is no part of the name or the text of the elements around it. In document order, at most limit (1 to 50, default 10); a warning says when more match. target chart (default) or window, the window chrome. INVALID_INPUT without a selector or a text, and for an invalid selector.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `selector` | string | no | A CSS selector the elements must match. With text, the elements that match it and have that name. 1 to 1000 characters. |
| `text` | string | no | The name the elements must have, equal to this. A name is its aria-label, or else the value of an input button, or else the text it shows, with a space between the texts of different elements and white space collapsed (a label made of Sell and 100 in two spans is "Sell 100"), or else its title, compared whole and ignoring case. 1 to 200 characters. |
| `target` | string | no | Which page to act on: chart (default) is the chart tab; window is the window chrome, the strip with the tabs of the app. One of: `chart`, `window`. |
| `limit` | integer | no | At most this many elements, from 1 to 50 (default 10). 1 to 50. |

### ui_open_panel

**Open or close a panel**

`Idempotent`

Opens or closes a panel of TradingView (open, true by default): watchlist (the watchlist, the details of a symbol and the news), alerts, object_tree, data_window (a tab of the panel of the object tree) and pine_editor. The first four go through the buttons of the right toolbar, clicked as ui_click clicks (a menu or a dialog over the toolbar refuses the click), and the panel is read afterwards until it shows as asked: opening the data window opens the panel of the object tree and selects its tab, and closing either collapses that panel. pine_editor opens the Pine Editor the way its button in TradingView does, showing the script it last held or a new one, and any unsaved text TradingView kept, and closes it without discarding its text: TradingView keeps unsaved text and shows it again on the next open. A panel that already is as asked is left alone, which changed false says. A panel counts as open while its button in the right toolbar shows it pressed, which is how app_get_ui_state reads its panels; for the Pine Editor, where its button does not say, while TradingView holds it in the side panel, or shows it at the bottom. An editor TradingView keeps hidden at the bottom is not shown again: open it in TradingView. CAPABILITY_UNAVAILABLE when the toolbar has no button for the panel or its button does not say whether it is pressed, when the panel of the object tree has no tab for the data window (the panel is collapsed again if it was opened to look), or when the Pine Editor has no way to close here, is hidden at the bottom, sits at the bottom where the page cannot say whether it is shown, or the page has no registry of open Pine editors; NOT_AVAILABLE while the toolbar is hidden, as in fullscreen mode, and when TradingView shows the Pine Editor but has no open editor to close; TIMEOUT when the panel does not change after the click. Returns panel, open and changed.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `panel` | string | yes | The panel: watchlist, alerts, object_tree, data_window or pine_editor (the Pine Editor). One of: `watchlist`, `alerts`, `object_tree`, `data_window`, `pine_editor`. |
| `open` | boolean | no | true (default) to open the panel, false to close it. |

### ui_evaluate

**Evaluate JavaScript in the chart tab**

`Destructive`

A power tool, off by default: runs JavaScript in the chart tab of TradingView and returns its value, for what no other tool reads. It is refused with CAPABILITY_UNAVAILABLE unless the server was started with TV_MCP_ALLOW_EVAL=true or --allow-eval, which only the user can do. It runs in the chart tab only, never in the window chrome, which has Node integration. The code runs in the user's live, signed-in page and can change anything the page can, so prefer the other tools, and read rather than change. expression is an expression, or statements whose last value is the result, as the console of the browser runs them; a promise is awaited. The page stops synchronous code that runs longer than the call timeout allows (PAGE_EVALUATION_FAILED), but code that runs after an await is not stopped. Before anything is sent, a denylist refuses with UNSAFE_ACTION_BLOCKED an expression that names the desktop bridge (TVD), the user object, user ids or names or session ids, cookies, the storage of the page (localStorage, sessionStorage, indexedDB), credentials (passwords, tokens, signing in, authentication), requests to the network (fetch, XMLHttpRequest, WebSocket, EventSource, sendBeacon, import()), Node.js (require, process, child_process, electron) or trading: the trading service of TradingView, its brokers, orders and positions (placeOrder, closePosition and the like), the order buttons (buy-order-button, trade-button and the like, which a click from the code itself would press past every guard of the input) and the buy and sell calls of the replay API. It knows the spacing, bracket, quote, joined-string, concat, comment and escaped forms of them: every one of these names is also looked for once quotes, brackets, parentheses, +, concat and comments are taken out, so that a name joined out of pieces is refused too. The denylist is best effort: it reads the text of the expression, and a name built in other ways while the code runs gets past it, so those objects themselves, the user object, the desktop bridge and the storage of the page, never come back in a value either, whatever the code reached them by: they are [withheld]. Only the objects are known: what the code reads out of them or copies is not recognised. Returns value, the result as JSON (undefined becomes null; a function or a DOM node its type, such as [object Function]; a date its ISO time; a map, a set or an error what they hold; [circular] where an object comes back into itself), at most 100 kB of it, and truncated, true when the value was cut to fit or nested deeper than 32 levels, with a warning. What the code throws is PAGE_EVALUATION_FAILED with its message, never a stack. Neither the expression nor the value is logged.

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `expression` | string | yes | The JavaScript to run in the chart tab, 1 to 10000 characters: an expression, or statements whose last value is the result. 1 to 10000 characters. |

## Batch (1 tool)

### batch_run

**Run tools in a batch**

`Destructive` `core`

Runs up to 20 tool calls one after another and returns the outcome of each. Use it to chain steps that would otherwise take several requests, for example switching the symbol and then the timeframe. Every step is validated and runs exactly like a direct call of its tool, so it needs the same arguments, confirmations included. By default the first step that fails stops the batch and the remaining steps are skipped; set stopOnError to false to run them all. batch_run cannot be one of its own steps. Steps run in order, so the batch takes as long as its steps together, and no step starts once 45 s have gone by, so that no client gives up on the call and sends its steps again: the steps not started come back as a warning, to send in another batch. Returns steps (one entry per step that ran, with tool, ok, and data or error), completed (how many steps ran) and stopped (true when the rest were skipped, after a failure or for the time).

| Input | Type | Required | Description |
| --- | --- | --- | --- |
| `steps` | object[] | yes | The tool calls to make, in the order they should run (1 to 20). 1 to 20 items. Fields: `tool` (string, required), `arguments` (object). |
| `stopOnError` | boolean | no | Stop at the first step that fails and skip the rest (default true). With false, every step runs whatever happened before it. |
